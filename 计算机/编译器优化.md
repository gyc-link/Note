# 编译器优化

## 引入

写完代码，编译器不是逐字翻译成机器码就完事了。它在中间会多做一步——**优化**（硬件无关的优化）。
### 什么是编译器

这里的"编译器"不是 Visual Studio

编译器是把一种语言翻译成另一种语言的程序。

Visual Studio 是 **IDE（集成开发环境）**——提供编辑器、编译器、调试器、项目管理。

### 编译器优化的定义

> [!important]- 什么是编译器优化
> 编译器在**保证程序结果不变**的前提下，把代码转换成**更高效的机器执行形式**。

C# 的编译优化发生在两个阶段，由两个不同的编译器负责：

| 阶段            | 编译器                  | 输入 → 输出           | 典型优化            |
| :------------ | :------------------- | :---------------- | :-------------- |
| **编译时 (AOT)** | Roslyn（`csc.exe`）    | C# 源码 → CIL（中间语言） | 常量折叠、死代码消除、函数内联 |
| **运行时 (JIT)** | RyuJIT（`clrjit.dll`） | CIL → 机器码         | 寄存器分配、循环展开、指令重排 |
> [!NOTE]
> Visual Studio 点"生成"按钮时，实际调的是 Roslyn 做第一步编译。点"运行"时，CLR 启动，JIT 再做第二步。Visual Studio 本身只是个壳。

> [!question]- 编译器什么时候优化
优化发生在编译时和运行时两个阶段，分别对应着C#源码->CIL中间语言和 CIL->机器码。

## 为什么需要编译器优化

程序员写代码时优先考虑的是可读性和逻辑清晰，不会刻意去手写"把 `1+2` 算好放那"这种事。编译器来干这些脏活。

```
你写的:                   编译器优化后:
int x = 1 + 2;           mov eax, 3        ← 直接给3，运行时不用算
int y = 60 * 60 * 24;    mov ebx, 86400    ← 编译期就算好了
```

> [!NOTE] 核心原则
> 怎么优化都行，但**程序运行的结果必须一模一样**。如果优化改变了行为，那就是编译器的 bug。

## 常见优化手段

### 1. 常量折叠 (Constant Folding)

编译期就能算出的常量表达式，直接在编译时求值，不必等到运行时再算。

```csharp
// 你写的
int seconds = 60 * 60 * 24;

// 编译后等价于
int seconds = 86400;
```

### 2. 死代码消除 (Dead Code Elimination)

永远不会执行到的代码，直接删掉。

```csharp
if (false) {
    DoSomething();  // ← 编译器：这行永远不会跑，删了
}
```

也包括定义了但从未使用的变量、函数。

### 3. 循环展开 (Loop Unrolling)

对于循环次数少或固定的循环，直接把循环体复制多份，省掉每次迭代的**计数器加 1 + 条件判断**开销。

```csharp
// 你写的
for (int i = 0; i < 4; i++) {
    sum += arr[i];
}

// 展开后等价于
sum += arr[0];
sum += arr[1];
sum += arr[2];
sum += arr[3];
```

> [!NOTE] 代价
> 代码体积变大。只对次数少或热路径上的循环做。

### 4. 函数内联 (Function Inlining)

调用函数是有成本的——参数压栈、跳转、执行、返回、出栈。内联直接把函数体复制到调用处，省掉这套流程。

```csharp
// 你写的
int Add(int a, int b) => a + b;
int result = Add(3, 5);

// 内联后等价于
int result = 3 + 5;
```

> [!warning] 不是所有函数都适合内联
> 递归函数、大函数内联会导致代码体积爆炸。编译器会权衡——小函数、调用频繁的优先内联。

> 程序执行到一个普通函数时，会压入 **Call Stack**（专门维护函数调用的栈），执行完毕后再出栈。函数内联就是减去这个出入栈的过程。

### 5. 公共子表达式消除 (Common Subexpression Elimination)

同一个表达式算了多次，只算一次，后面复用结果。

```csharp
// 你写的
int x = a * b + c;
int y = a * b + d;

// 优化后
int temp = a * b;
int x = temp + c;
int y = temp + d;
```

### 6. 寄存器优化 (Register Allocation)

CPU 里的寄存器是读写最快的存储单元。编译器会分析哪些变量用得最频繁，优先分配寄存器给它们，减少内存读写次数。

### 7. 指令重排 (Instruction Scheduling)

在不影响结果的前提下，调整指令的执行顺序，充分利用 CPU 流水线，减少等待。

## Release vs Debug

> [!important]
> - **Debug 版本**：包含调试信息（符号表、断点支持），优化很少甚至没有——方便单步调试。
> - **Release 版本**：去掉调试信息，编译器优化全开——面向最终用户，追求运行速度。

这也是为什么有些 bug 只在 Debug 出现，有些只在 Release 出现——两种模式下的内存布局和执行顺序可以完全不同。

## 优化的边界

编译器优化再强，也有它做不到的事：

- **不能跨编译单元优化**：不同 `.cs` 文件（不同编译单元）之间，编译器很难做全局优化。
- **不能优化算法复杂度**：O(n²) 不会变成 O(n log n)——那是程序员的事。
- **不能违反语言语义**：比如多线程下的内存可见性，编译器必须尊重语言规范。
