# CPU

## 引入

中央处理器（CPU）就是电脑的大脑——一块指甲盖大小的芯片，只做一件事：**执行指令**。

C# 代码，经过编译变成一串机器指令。CPU 的工作就是一条条把它们吃进去、算完、吐出来。一秒跑几十亿次。

## CPU 里面有什么

拆开看，CPU 内部就三样东西：

```
                 ┌──────────────────┐
                 │       CPU        │
                 │                  │
   指令进来 ──→  │  ┌────────────┐  │
                 │  │   控制器    │  │  ← 指挥中心，"接下来干什么"
                 │  └─────┬──────┘  │
                 │        │         │
                 │  ┌─────▼──────┐  │
                 │  │   运算器    │  │  ← 真正干活的，算术+逻辑
                 │  │  (ALU)     │  │
                 │  └─────┘      │  │
                 │               │  │
                 │  ┌───────────┐│  │
                 │  │  寄存器组  ││  │  ← 干活用的"工作台"
                 │  └───────────┘│  │
                 └──────────────────┘
```

- **控制器**：指挥。按节拍（时钟）看当前轮到哪条指令，通知其他部件行动。
- **运算器（ALU）**：执行。加减乘除、比大小、与或非，全在这干。
- **寄存器组**：工作台。ALU 旁边极快的小格子，存操作数和结果。

> [!NOTE] 时钟
> CPU 按固定节拍工作，这个节拍就是时钟频率。3.5 GHz 意味着 1 秒打 35 亿个拍子——每个拍子都可能完成一步操作。

## 一条指令怎么跑完的

以 `int x = 1 + 2` 为例，CPU 跑一遍背后的流程：

```
取指令 ──→ 译码 ──→ 执行 ──→ 写回 ──→ 取下一条
  │         │        │        │
  │         │        │        └── 结果写进寄存器 x
  │         │        └── ALU 把 R1(1) 和 R2(2) 相加，得 3
  │         └── 控制器解码：这要做加法，1 和 2 得先搬进寄寄存器
  └── 从内存里捞出这条加法指令
```

> [!important] 关键
> ALU 不直接操作内存——操作数必须先从内存搬进寄存器，算完结果也先进寄存器。寄存器是 ALU 和内存之间的**中转站**。

## 寄存器：CPU 的工作台

寄存器就是 CPU 内部的一组"小格子"，跟 CPU 同频工作，读写只要一个时钟周期。相比之下，去内存拿数据要等几百个周期。

**常用的几种寄存器：**

| 寄存器 | 干什么 |
|:---|:---|
| 通用寄存器 | 放操作数和中间结果（干活用的） |
| 指令指针 (IP) | 记住"下一条指令在哪" |
| 栈指针 (SP) | 记住"函数调用栈顶在哪" |
| 状态寄存器 | 记运算后的零、进位、溢出等标志 |

> 调用 `obj.Method(a, b)` 时，`obj`（this）、`a`、`b` 都塞进寄存器，然后 CPU 跳转到方法代码——这就是"寄存器传递 this 指针"。

## 数据怎么流动的：存储层级

CPU 做计算时，数据是从不同地方搬来的。越近越快、越远越慢：

```
速度    容量     位置
快 ↑   小
  寄存器     ~几十个           CPU 内部，同频
  L1 缓存   ~几十 KB           CPU 内部
  L2 缓存   ~几百 KB           CPU 封装内
  L3 缓存   ~几 MB             CPU 共享
  内存      ~几 GB~几十 GB     主板插槽
  硬盘      ~几百 GB~几 TB     持久存储
慢 ↓   大
```

寄存器比内存快约 300 倍。所以编译器会尽量把热点变量放在寄存器里——这就是[[../编译器优化]]里提到的寄存器分配。

## 跟写代码有什么关系

写 C# 不直接碰寄存器，但它影响你写的每一行：

- 局部变量、小循环可能全程在寄存器里跑完，快得飞起
- 大 struct 传值慢——塞不进寄存器，得在内存里反复拷贝
- Debug 和 Release 跑出来不一样——寄存器分配策略不同，可能影响浮点精度和多线程可见性
