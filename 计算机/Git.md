## 引入

设想你在写一篇论文，每天都要改。某天你改到一个地方，突然想不起"上周的版本里这句话是怎么写的"——而文件已被覆盖，没法回头。

Git 做的事：**每次"保存"都是一次快照**，可以随时回到任意一个历史版本。更关键的是，Git 让**多人并行修改**同一份代码而不会互相覆盖。

>[!important] 关键
>Git 不是"存差异"，而是**存快照**——每次提交保存的是整个项目在那一刻的完整状态。
>如果文件没变，只存一个指向之前版本的引用（指针/索引），避免重复存储。比如项目中100个文件，只改动了其中一个文件，其他99个文件只保存指向之前旧版本位置的指针。


## 基础概念

### 四个区域

Git 把文件分成四个工作区域，数据在区之间流动：

![[dot/四区域.svg]]

>[!help]- 暂存区（Staging Area / Index）是什么
>暂存区是"准备做成下一次提交的文件清单"。`git add` 把文件放进暂存区，`git commit` 把暂存区的内容打包成一个提交对象。它让你**精确控制**这次提交要包含哪些改动，而不是"所有修改一股脑提交"。

### 提交（Commit）

提交是 Git 的最小存储单元。

>[!question]- 每个提交包含
>- 一个完整的项目快照
>- 作者、提交者、时间戳
>- 一条提交说明
>- 一个或多个**父提交**的 SHA-1 哈希值（merge commit 有两个父提交），所以多个Commit串起来，就形成了历史。

>[!question]- SHA-1哈希的作用
>Git 用 **SHA-1 哈希**（40 位十六进制）标识每个对象。相同内容 → 相同哈希 → 相同的内容地址存储。这意味着 Git 天然防篡改——改了任何一个比特，哈希就完全变了。

## Git 的数据模型（底层）

### 四种对象

Git 内部只有四种对象，Git 内部以键值对（KV 存储）形式存放在 `.git/objects/` 目录中——键是 SHA-1 哈希，值是压缩后的内容：

![[dot/四对象.svg]]

>[!question]- Git数据模型
>| 对象         | 存储内容                                | 标识          |
| ---------- | ----------------------------------- | ----------- |
| **blob**   | 文件内容（不含文件名）                         | 文件内容的 SHA-1 |
| **tree**   | 目录结构：文件名 + 权限 + 指向 blob/subtree 的哈希 | 目录内容的 SHA-1 |
| **commit** | 一次提交的快照：指向一棵 tree + 元信息 + 指向它的前一次提交             | 提交内容的 SHA-1 |
| **tag**    | 附注标签：指向一个特定的Commit对象，作为固定的版本标记      | 标签内容的 SHA-1 |

## 分支

### 分支是什么

**书签比喻**：分支 = 书签（有很多个，各插在不同页），HEAD = 此刻捏在手里的那个书签。翻到新的一页后，当前书签就更新到新位置。

>[!help]- 分支的本质
>分支不是"容器"，分支是一个**指针/引用**，存放在 `.git/refs/heads/` 下，文件内容存放着最新一次提交的commit 哈希值。每次在分支上做新提交，分支指针就自动前移到最新提交。

示例：
![](../pic/Pasted%20image%2020260630094923.png)


### HEAD 与分支的关系

>[!important] 切换分支就是让HEAD头指针指向另一个分支
>**HEAD → 分支 → 提交**（两层间接）。HEAD 指向当前正在操作的分支，分支指向某个提交。
>切换分支 = HEAD 改指向另一个分支，工作区内容调整成那个分支对应提交的样子。

### Detached HEAD（分离头指针）

>[!help]- 什么是分离头指针？
>头指针不指向分支，而是直接指向Commit
>

>分离头指针触发方式：`git switch --detach <commit-hash>` 或 `git checkout <commit-hash>`。

>[!warning] 分离状态的风险
>如果此时做新提交，没有分支指向它 → 提交变成"悬空提交"，切换走之后就找不到了（只能靠 reflog 找回）。
>**解决**：在分离状态下 `git switch -c 新分支名`，给当前提交挂上一个分支。

### 三种分支概念

| 概念         | 存放位置                           | 说明                                |
| ---------- | ------------------------------ | --------------------------------- |
| **本地分支**   | `.git/refs/heads/xxx`          | 你在本机操作的分支，可随意创建、合并、删除             |
| **远程跟踪分支** | `.git/refs/remotes/origin/xxx` | 远端状态的**本地镜像**，只读。通过 fetch/push 更新 |
| **远程分支**   | GitHub/GitLab 远端仓库             | 远端真正的分支，别人也看得到                    |

>[!warning] 常见混淆
>`origin/main` ≠ 远端真正的 `main`。`origin/main` 是你上次 `git fetch` 时远端的样子，可能已经过时。`origin` 是远程仓库 URL 的**代号**，不是真实仓库。

### 上游分支（Upstream / Track）

上游分支 = 本地分支与远端分支的**关联关系**。设好后 `git push/pull` 不用每次指定远端和分支名。

>[!info] 三种设法的本质一样（设置上游），只是时机不同：
>- `git checkout --track origin/feature` — **创建分支时**用
>- `git push -u origin feature` — **第一次推分支时**用
>- `git branch -u origin/feature` — **分支已存在后补设/修改**时用

### 常用分支命令

| 命令 | 作用 |
|------|------|
| `git branch` | 列出所有本地分支 |
| `git branch -a` | 列出所有分支（含远程跟踪分支） |
| `git branch 新分支名` | 基于当前位置创建新分支（不切换） |
| `git switch -c 新分支名` | 创建并切换到新分支 |
| `git switch 分支名` | 切换到已有分支 |
| `git branch -d 分支名` | 删除已合并的分支（安全） |
| `git branch -D 分支名` | 强制删除分支（即使未合并） |
| `git branch -m 新名称` | 重命名当前分支 |
| `git branch -vv` | 查看所有本地分支及其上游跟踪关系 |

## 合并与变基

### Merge（合并）

`git merge` 把另一个分支的提交**合并到当前分支**。

![[dot/Merge.svg]]

| 方式               | 条件               | 结果                                                   |
| ---------------- | ---------------- | ---------------------------------------------------- |
| **Fast-forward** | 当前分支没有新提交，目标分支领先 | 分支指针直接前移，不产生新 commit，历史线性                            |
| **3-way merge**  | 两个分支各自都有新提交      | 找共同祖先（base），对比 base→A 和 base→B 的变化，生成新的 merge commit |

`git merge --no-ff`：强制生成 merge commit，即使可以 fast-forward。用于保留"这个功能是一个分支开发"的历史痕迹。

### Rebase（变基）

>[!help]- 什么是 rebase
>`git rebase` = 把当前分支的提交"摘下来"，**接到目标分支的最新提交后面**，就像是从目标分支最新节点开始重新"长"了一遍。

![[dot/Rebase.svg]]

### Merge vs Rebase

|        | Merge               | Rebase              |
| ------ | ------------------- | ------------------- |
| **历史** | 保留真实的分叉历史           | 重写历史，变成一根线          |
| **结果** | 两条线 + 一个合并点         | 线性历史，更整洁            |
| **适合** | 公共分支（main/dev），多人协作 | 个人分支整理，让 review 更轻松 |

>[!warning] 黄金规则
>**不要对已经推送到远端共享分支的提交做 rebase**。变基会改变提交哈希 → 别人的历史跟你的对不上 → 灾难。

### 合并冲突（Merge Conflict）

两个分支（本质是两个Commit）**修改了同一文件的同一行**，Git 无法自动决定用哪个版本 → 标记为冲突。

冲突标记：
```
<<<<<<< HEAD          （当前分支的版本）
你的代码
=======               （分隔线）
目标分支的代码
>>>>>>> feature       （目标分支名）
```

解决流程

```
- 打开冲突文件，手动编辑保留想要的代码，删掉 `<<<<<<<`、`=======`、`>>>>>>>` 标记
- `git add 冲突文件` 告诉 Git "已解决"
- merge 场景：`git commit` / rebase 场景：`git rebase --continue`
- 想放弃：`git merge --abort` 或 `git rebase --abort`
```

## 远程协作

### Fetch vs Pull

>[!help]- fetch 和 pull 的区别
>- `git fetch`：只从远端**下载**最新数据到本地 `.git`（更新 `origin/xxx` 远程跟踪分支），**不动你的工作区和当前分支**。安全——先看看别人改了什么。
>- `git pull` = `git fetch` + `git merge`（两步合一步）。直接把远端改动拉到当前工作分支。

> 建议：多看少动 → 先 `git fetch`，再 `git diff origin/main` 看看差异，确认没问题了再 `git merge`。

### Push

`git push`（默认 `push.default=simple`）只推送**当前分支**上远端没有的新提交，不是所有分支的所有提交。

工作原理：Git 对比本地分支和远端跟踪分支的差异 → 打包差异提交 → 发送到远端 → 同步指针。

>[!warning]- Push 被拒绝
>如果远端有新提交而本地没有（别人推了），直接 push 会被**拒绝**。必须先 `git pull`（= fetch + merge）拉取并合并，解决可能冲突后，再 push。

### Tag

>[!help]- tag 是什么？和分支有什么区别？
>tag 是给某一次提交贴一个**固定名字**，主要用于标记发布点（v1.0, v2.0 等）。
>**关键区别：tag 不会移动，分支会。** 新提交后分支自动前移；tag 永远钉在当初标记的那个提交上。

## 实用操作

### Git 基础命令格式

```
git <子命令> [选项] [参数]
```

- 子命令：config, commit, push, branch, switch...
- 选项：`--local`、`--list`、`--show-origin`...
- 参数：`user.name`、分支名...

### 配置用户信息

```bash
# 当前项目
git config user.name "你的名字"
git config user.email "你的邮箱"

# 全局
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

# 绑定远程仓库
git remote add origin https://github.com/<用户名>/<仓库名>.git
```

### SSH 连接 GitHub

SSH 基于密钥验证，连接比 HTTPS 更稳定，配置后无需反复输入账号密码。

```bash
# 1. 生成 SSH 密钥
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 2. 将公钥添加到 GitHub（Settings → SSH Keys）

# 3. 切换仓库为 SSH 地址
git remote set-url origin git@github.com:<用户名>/<仓库名>.git

# 4. 验证
git remote -v

# 5. 测试连接
ssh -T git@github.com
```

>[!help]- SSH 密钥验证原理
>1. 把**公钥**放到服务器上
>2. 登录时，服务器用公钥加密一段信息发给你
>3. 用**私钥**解密并回应
>4. 验证通过 → 免密登录


### .gitignore

`.gitignore` 是一个黑名单文件——**里面写的文件/文件夹，Git 会假装没看见，不提交。**
