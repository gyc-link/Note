# 网络

## 网络基础概念

> 以下概念按理解网络隔离和抓包工具的依赖关系排列：先搞懂 IP 和网络分层，再理解代理和抓包，最后理解防火墙规则。

### IP 地址 — 每台设备的"门牌号"

连网的每台设备都有一个 IP 地址，比如 `192.168.1.5`。它由四个 0~255 的数字组成，像门牌号一样，让数据知道该送到哪。

IP 分两种：
- **公网 IP**：全世界唯一，互联网上的"收件地址"。你家的路由器有一个
- **私网 IP**：只在你家里/公司里有效，出门无效。你的电脑、手机的 IP 都是这种

**私有 IP 三段范围**（RFC 1918 规定，全世界路由器遵守）：

| 范围                        | 说明                    |
| ------------------------- | --------------------- |
| `10.x.x.x`                | 公司/学校大型内网（1600 多万个地址） |
| `172.16.x.x ~ 172.31.x.x` | 中型内网（100 万个地址）        |
| `192.168.x.x`             | 家用路由器默认，最常见（6 万多个地址）  |

怎么知道我家是哪个？终端打 `ipconfig`，看"IPv4 地址"那行。大概率是 `192.168.x.x`。

### 子网掩码 — "哪些邻居算我们家人"

子网掩码是一张"范围说明纸"，告诉设备：哪些 IP 是家里人可以直连的，哪些要出门找路由器。

比如 `255.255.0.0` 的意思是：IP 地址的前两位相同的设备都是家里人。`192.168.1.5` 和 `192.168.2.8` 前两位相同（都是 192.168），所以它们在一个网里。

`/16` 是同一意思的缩写（CIDR 记法，无类别域间路由），`192.168.0.0/16` = 前 16 位（也就是前两个数字）锁定，后面随便。Windows 防火墙对 `/16` 支持不好，要用 `255.255.0.0` 这种写法。

### 网关 — 家里的"大门"

网关就是你家的路由器地址，通常是 `192.168.1.1`。所有要出外网的数据，都从这扇门出去。

### NAT — "替全家出面的人"

你家只有**一个**公网 IP（路由器从运营商那拿到的），但家里可能有五六台设备——电脑、手机、电视、平板。它们怎么同时上网？靠 NAT（网络地址转换，Network Address Translation）。

你手机发一个请求出去：
1. 手机用私网 IP（`192.168.1.5:50000`）发到路由器
2. 路由器把 `192.168.1.5:50000` 换成 `公网 IP:60000`，记到一张表里
3. 服务器回复给 `公网 IP:60000`
4. 路由器查表——"60000 端口是我刚才替手机开的"——把回复还给手机

全家设备共用同一个公网 IP，靠不同的临时端口号区分"这是谁的回复"。外面的人不知道你家有几台设备，只看到路由器一台。这就像一个公司只有一部座机，前台替所有人转接。

**NAT 的副作用**：
在默认情况下，外部网络（公网）的任何设备都**无法主动**找到或连接到 NAT 后面的子设备（私网设备）。
因为路由器不知道把请求转发给谁——除非你手动设置了端口转发。这也是为什么 P2P 下载、网游联机有时候要折腾"端口映射"。

### DHCP — "自动发门牌号的人"

路由器上跑着一个叫 DHCP 的服务。设备一连 WiFi，就向路由器"要一个 IP"。路由器从自己兜里掏一个没被占用的号（比如 `192.168.1.10`），发给设备，设置好子网掩码和网关。全程不用你管。

如果没有 DHCP（比如新建了一个内部交换机），设备要不到地址，系统会随机给自己编一个 `169.254.x.x` 开头的号——这叫 **APIPA**（自动私有 IP 地址）。这个地址无效，上不了网，网关也是空。

### MAC 地址 — 设备的"身份证号"

IP 地址是"你在哪"（会变，换个 WiFi 就换了），MAC 地址是"你是谁"（出厂烧在网卡上，不变）。局域网内部最终是靠 MAC 地址通信的。

### 协议 — 数据的"说话方式"

数据在网上传输有不同的"说话方式"，叫协议。三个最常用：

| 协议 | 全称 | 特点 | 常见用途 |
|---|---|---|---|
| TCP | 传输控制协议 | 可靠、有序，像挂号信——对方收到会确认 | 网页、下载、邮件 |
| UDP | 用户数据报协议 | 快但不保证送达，像往信箱丢明信片 | 视频通话、直播、游戏 |
| ICMP | 互联网控制报文协议 | 纯粹用来探测：你在不在？ | `ping` 命令 |

### 端口 — 同一台设备上的"不同窗口"

IP 找到设备，端口找到设备上的**哪个程序**。一台服务器可以同时跑网页（端口 443）、邮件（端口 25）、数据库（端口 3306）——IP 相同，端口不同，就能区分"给网页的数据"和"给数据库的数据"。

### HTTP 与 HTTPS

HTTP 是浏览器和服务器之间传输网页的协议。HTTPS 是加了一层 **SSL/TLS 加密**的 HTTP——通信内容被加密，中间人截获了也看不懂。

每一次 HTTP 通信是一封信：

| 部分 | 类比 | 放了什么 |
|---|---|---|
| Header | 信封 | 发给谁、什么格式、多长、用什么密钥 |
| Body | 信纸 | 真正要传的数据——对话内容、密码、API Key |

HTTPS 把**信封 + 信纸一起锁进保险箱**。只有你和服务器有钥匙。所以抓包工具默认看不到 Body——不是空的，是加密了你看不见。

### 代理 — "中间传话人"

代理服务器就是站在你和外网之间的"传话人"。你让它帮你发请求，它发出去，再把结果拿回来给你。

系统级的 HTTP 代理（Proxyman 就起了一个）会截走所有设置了代理的程序流量。但 Hyper-V 外部交换机在更底层——VM 的流量直接走物理网卡，根本不经过你主机上的代理。所以**主机上开 Proxyman 抓不到 VM 的包**。

### 防火墙 — "看门大爷"

防火墙就是一套检查进出流量的规则。

- **入站规则**：外面有人敲门，让不让进
- **出站规则**：里面的人往外跑，让不让出

每条规则要指定三个东西：从哪来的、往哪去的、用什么协议。Windows 防火墙的"远程 IP"指的是**目的地**，不是来源。"本地 IP 留空，远程 IP 填内网段"的规则就是在说：从本机出发，目的地是局域网 → 不许走。

> 主机防火墙管不到 VM。VM 走外部交换机时，流量不经过主机的网络栈，直接在物理网卡上跑。要在 VM 里面加防火墙规则才行。

## 抓包工具原理（Proxyman / Fiddler）

抓包工具把自己插在你和服务器之间，解密、记录、再加密发走——**MITM（中间人攻击）**，只是你在自己电脑上攻击自己。

HTTPS 正常是加密直连。抓包工具往你系统里装了一根它自己的根证书。浏览器本来就信任几根根证书（由 CA 管理），抓包工具的根证书加入信任列表后，它就能给任何域名签发临时假证书，浏览器照样放行：

```
你 ←→ 抓包工具（假证书A）←→ 目标服务器（真证书B）
     加密           明文             加密
```

在抓包工具手里，数据是明文的。

使用要点：
- **限制解密范围**：`Tools → Allow List`（白名单），只让关心的域名出现在视图里，其余流量绕开不碰
- **Proxyman 抓不到虚拟机流量**：VM 走外部交换机，流量绕过主机代理

## SSH 端口与协议

443端口是HTTPS协议的端口，用于加密传输数据。
80端口是HTTP协议的端口，用于传输明文数据。
22端口是SSH协议的端口，用于加密传输数据。

网络运营人员通常会将22端口关闭，以提高系统的安全性。
GitHub 为了解决全球各地网络屏蔽 22 端口的问题，专门提供了一个备用方案：`ssh.github.com:443`

这个地址，本质是 GitHub 在 443 端口上，跑了一个能识别 SSH 流量的服务，让 SSH 数据包伪装成 HTTPS 流量，绕过网络屏蔽。

## Hyper-V 网络隔离

三种虚拟交换机：

| 类型 | VM↔主机 | VM↔局域网 | VM↔外网 | 本质 |
| --- | --- | --- | --- | --- |
| 外部 | 通 | 通 | 通 | VM 直接绑物理网卡，路由器给它发 IP |
| 内部 | 通 | 不通 | 不通 | VM 只能跟主机说话 |
| 专用 | 不通 | 不通 | 不通 | 仅 VM 之间通信 |

**外部 = 桥接**，VM 在局域网上跟你主机平起平坐。这也是为什么需要给 VM 加出站规则——它就像一个独立的邻居，你得管它家的大门。

新建 Hyper-V 内部交换机后没有 DHCP → VM 生成 APIPA（`169.254.x.x`），上不了网。

**VM 出站规则：禁止访问局域网**（前提：VM 用外部交换机，规则加在 VM 里面）：
1. VM 内打开 `高级安全 Windows Defender 防火墙` → 出站规则 → 新建
2. 程序：跳过 → 协议类型：`任何`
3. 远程 IP 地址：`192.168.0.0/255.255.0.0`、`10.0.0.0/255.0.0.0`、`172.16.0.0/255.240.0.0`
4. 本地 IP 地址：留空 → 操作：阻止 → 三配置文件全勾 → 命名

**测试**：`ping 8.8.8.8` 应通（外网 OK），`http://192.168.x.1` 应打不开（局域网已阻断）

> 不需要外网的话，直接把虚拟交换机从"外部"改成"内部"——物理层面隔离。但注意外网也会断，只有主机能跟 VM 通信。
