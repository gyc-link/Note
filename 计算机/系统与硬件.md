# 系统与硬件

## 系统 / 硬件操作

- 装系统：台式机按`delete`进 BIOS 改启动项；分区 ：装机时不要分区，系统盘左右会有间隔；UEFI 引导对应 GPT 分区，Legacy 对应 MBR 分区；可通过`shift+f10`执行`list disk`/`select disk`/`clean`/`convert gpt/mbr`命令；推荐微 PE，系统镜像从 MSDN / 微软官网下载。
- 显示器 / 主机：主板 / 显卡有 HDMI 接口，显卡多 DP 接口；主机接口对应 CPU 核显，BIOS 中开启核显支持多屏显示。

## x86 vs x64 架构

>[!question]- 32 位和 64 位的核心区别
>CPU 一次能处理的**地址宽度**。

- **32 位操作系统**：地址总线 32 位，最多寻址 2³² = **4 GB** 内存。插再多内存条，系统也用不上。
- **64 位操作系统**：理论寻址 2⁶⁴ = 16 EB（160 亿 GB）。实际实现中，当前 x86-64 CPU 只用 48 位做虚拟地址（256 TB），够用了。

> 所以老机器装 32 位系统、配 4 GB 以上内存是浪费——系统根本看不见多余的内存。

**二进制单位换算**（计算机里都是 1024 进制）：

| 简写 | 二进制单位 | 字节数 | 2 的幂 |
|------|-----------|--------|--------|
| **1 K** | 1 KiB | 1,024 | 2¹⁰ |
| **1 M** | 1 MiB | 1,048,576 | 2²⁰ |
| **1 G** | 1 GiB | 1,073,741,824 | 2³⁰ |
| **1 T** | 1 TiB | 1,099,511,627,776 | 2⁴⁰ |

> 硬盘厂商用十进制（1 K = 1000），所以买到的 1 TB 硬盘插电脑上显示约 931 GB——不是少了，是单位不同。

## 显示器

**光学三原色：RGB**。显示器上每个像素由红、绿、蓝三个子像素组成，调节各自亮度混合出所有颜色。这是**光的加法混合**——三色全亮 = 白色，全灭 = 黑色。

**原生分辨率**：显示器面板上实打实的发光点数量。4K 显示器物理上有 3840×2160 个像素点。系统里把分辨率调低后，GPU 画一张小画面，显示器硬件把它拉伸填满物理像素——所以会糊。**LCD 显示器只有在原生分辨率下才最清晰。**

>[!NOTE]- **屏幕尺寸**：
>常说的"多少英寸"指的是屏幕**对角线**的长度，不是长也不是宽。

**GPU 为什么能同时算那么多像素**：GPU 有几千个小核，每个核管屏幕上一小片格子。渲染时所有核同时开工，各算各的格子颜色——这就是"并行计算"。CPU 核少但每个核很强（处理复杂逻辑），GPU 核多但每个核很简单（做大量重复计算）。

## 抗锯齿

显卡在渲染画面时，为了消除物体边缘的"锯齿"（即像素化带来的阶梯状线条），会对每个像素点进行多次采样和计算。抗锯齿开得越高，显卡为了消除锯齿，在单位时间内需要处理的有效像素样本越多。

aliasing `/ˈeɪliəsɪŋ/`
多重采样抗锯齿（MSAA，Multi-Sampling Anti-Aliasing）：它只针对物体的边缘像素进行倍增采样。

如果开到 MSAA x 8，意味着显卡会对边缘像素进行 8 次 子像素采样，然后混合计算出最终的颜色。在这种情况下，并不是所有像素都计算8倍。屏幕上的非边缘区域（如大面积的天空或墙壁）依然只计算1次。但即便如此，当画面复杂时，显卡需要实时判断哪些是边缘，并对边缘进行高倍采样，计算量依然会大幅增加。

超级采样抗锯齿（SSAA，Super-Sampling Anti-Aliasing）
以高于目标分辨率的画面渲染，再降采样到目标分辨率。效果最好但性能开销最大。

时域抗锯齿（TAA，Temporal Anti-Aliasing） 和 深度学习超级采样（DLSS，Deep Learning Super Sampling）/ FSR（FidelityFX Super Resolution）
- TAA：利用上一帧的画面信息来辅助当前帧的抗锯齿，性能开销小，但可能导致运动模糊/拖影。
- DLSS/FSR：通过AI/算法将低分辨率画面重建为高分辨率，兼具抗锯齿和性能提升。

## CPU 缓存与数据结构性能

**数组遍历为什么比链表快？** 

答案在 CPU 缓存。

```
【内存】: [ 数组0 ][ 数组1 ][ 数组2 ][ 数组3 ][ 数组4 ][ 数组5 ]
              │        │        │        │
            ┌─┴────────┴────────┴────────┴─┐
            │  CPU 预读机制：打包一并带走    │
            └──────────────┬───────────────┘
                           ▼
【CPU 缓存】: [ 数组0 ][ 数组1 ][ 数组2 ][ 数组3 ]  ← 极速读取！
                           │
                           ▼
                    【 CPU 核心 】

结果：只有访问数组0 可能发生一次 Cache Miss，接下来的 1、2、3 全部 Cache Hit
```

```
【内存】: [ 节点1 (去A区) ] ...... [ 节点2 (去B区) ] ...... [ 节点3 ]
                │                          ▲
                └──────────────────────────┘ (顺着指针寻找)

            ┌──────────────────────────────┐
            │ CPU 预读：只能打包节点1周围的   │
            │ 无用垃圾数据，根本找不到节点2    │
            └──────────────┬───────────────┘
                           ▼
【CPU 缓存】: [ 节点1 ][ 内存邻居甲 ][ 内存邻居乙 ] ← 没能提前加载节点2！
                           │
                           ▼
                    【 CPU 核心 】 ──> 找不到节点2！触发 Cache Miss！
                                       被迫再次调头去主存搜寻...
```

每访问一个节点就要顺着指针去内存的新地方现找。上次预读进 Cache 的数据全部浪费，每次访问大概率伴随 Cache Miss。

> 核心原因：数组元素在内存中是**连续存放**的，CPU 一次预读能拉一批进缓存。链表节点**散落在内存各处**，指针指向哪就得跳到哪，CPU 的预读机制完全帮不上忙。

## 深入理解计算机系统（CSAPP）

### 信息 = 位 + 上下文

系统中所有的信息——磁盘文件、内存中的程序、内存里存放的用户数据、网络上传送的数据——都是由**一串比特**表示的。**区分不同数据对象的唯一方式，是我们读到这些数据对象时的上下文。**

同一串 bit，在不同上下文里可以是数字、是文字、是指令。只由 ASCII 字符构成的文件叫**文本文件**，其余的都叫二进制文件。

### 编译系统：GCC 的四个阶段

GCC 编译器驱动程序读取源程序文件，把它翻译成可执行目标文件，分四个阶段：

```
源程序 → 修改后的源程序 → 汇编程序 → 可重定位目标程序 → 可执行目标程序
        (预处理器)        (编译器)   (汇编器)          (链接器)
```

GCC 是 GNU 项目开发出来的工具之一。

### 系统的硬件组成

贯穿整个系统的是一组电子管道，称作**总线**，它携带信息字节并负责在各个部件间传递。总线通常被设计成传送**定长的字节块**。

主要部件：**I/O 设备、主存、处理器**。

>[!important] DMA
>**DMA 技术可以让存储在磁盘上的数据不经过处理器，直接到达主存。**

系统花了大量时间在"把信息从一个地方挪到另一个地方"：hello 程序的机器指令最初放在磁盘上，程序加载时被复制到主存；处理器开始运行程序时，指令又从主存复制到处理器。

### 高速缓存（Cache）

主存和处理器之间的速度差异很大，系统设计者采用了更小更快的存储设备——**高速缓存存储器（cache memory）**，作为暂时的集结区域，存放处理器近期可能会需要的信息。位于处理器芯片上的 L1 高速缓存容量比寄存器多得多，访问速度却跟访问寄存器差不多。

**存储器层次结构的主要思想是：上一层的存储器，作为下一层存储器的高速缓存。**

### 操作系统管理硬件

可以把操作系统看成应用程序和硬件之间插入的一层软件。所有应用程序对硬件的操作尝试都必须通过操作系统。它做两件事：

1. 防止硬件被失控的应用程序滥用
2. 向应用程序提供简单一致的机制，来控制复杂而又通常大不相同的低级硬件设备

操作系统通过几个基本抽象概念来实现这两个功能——**进程、虚拟内存、文件**：

| 抽象 | 对应什么 |
| --- | --- |
| 进程 | 对处理器、主存和 I/O 设备的抽象 |
| 虚拟内存 | 对主存和磁盘 I/O 设备的抽象 |
| 文件 | 对 I/O 设备的抽象 |

### 进程与线程

>[!definition] 进程
>进程是操作系统对一个**正在运行的程序**的一种抽象。在一个系统上可以同时运行多个进程，而每个进程都好像在独占地使用硬件。

**并发运行**是指一个进程的指令和另一个进程的指令**交错执行**：

```
进程A：█░░░█░░░█░░░
进程B：░█░░░█░░░█░
时间 →
```

大多数系统里，需要运行的进程数多于可以运行它们的 CPU 个数。一个 CPU 看上去能并发执行多个进程，是通过处理器在**进程间切换**实现的。因为 CPU 每秒切换几百万甚至上亿次，短时间内每个进程都推进了。

操作系统保持跟踪进程运行所需的所有状态信息，这种状态就是**上下文**——包括 PC 和寄存器文件的当前值，以及主存的内容。操作系统决定把控制权从当前进程转移到新进程时，会进行**上下文切换**：保存当前进程的上下文 → 恢复新进程的上下文 → 把控制权交给新进程。

>[!example] shell 与 hello
>最开始只有 shell 进程在运行，等待命令行输入。当我们让它运行 hello 程序时，shell 通过调用**系统调用**来执行请求，控制权传递给操作系统。操作系统保存 shell 进程的上下文，创建新的 hello 进程及其上下文，把控制权传给 hello。hello 终止后，操作系统恢复 shell 进程的上下文，把控制权传回给它。

**线程**：现代系统中，一个进程实际上可以由多个称为**线程**的执行单元组成，每个线程都运行在进程的上下文中，并共享同样的代码和全局数据。

>[!note] 进程 vs 线程
>| | 进程 | 线程 |
>| --- | --- | --- |
>| 概念 | 操作系统**分配资源**的基本单位 | CPU **调度**的基本单位 |
>| 资源 | 独立内存空间 | 共享所属进程的内存 |
>| 开销 | 创建/切换开销大 | 创建/切换开销小（轻量级） |
>| 通信 | 需 IPC（管道、Socket 等） | 直接读写共享变量 |
>| 独立性 | 一个进程崩溃不影响其他 | 一个线程崩溃通常导致整个进程挂掉 |
>
>一个进程至少有一个线程（主线程）。多线程共享堆内存，所以有并发安全问题。

### 虚拟内存

**虚拟内存**是一个抽象概念，它为每个进程提供了一个假象：**每个进程都在独占地使用主存**。每个进程看到的内存是一致的，称为**虚拟地址空间**。

在 Linux 中，地址空间最上面的区域保留给操作系统中的代码和数据，这对所有进程来说都一样；底部区域存放用户进程定义的代码和数据。从下往上依次是：

```
程序代码和数据 → 堆 → 共享库 → 栈 → 内核虚拟内存
```

### 并发与并行

- **并发（Concurrency）**：一个同时具有多个活动的系统
- **并行（Parallelism）**：用并发来使一个系统运行得更快

| | 并发 | 并行 |
| --- | --- | --- |
| 关注点 | 任务调度、响应速度 | 计算吞吐、性能 |
| 执行方式 | 时间片轮转，交替执行 | 多核同时执行 |
| 硬件要求 | 单核即可 | 必须多核 |
| 比喻 | 一个人同时下三盘棋 | 三个人分别下三盘棋 |
