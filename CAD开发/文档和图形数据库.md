## 1. 创建和访问图形数据库


### 1.1 数据库的初始状态

当一个图形数据库被新建时，包含了下面的基本数据
- 9个符号表，其中一些符号表会拥有初始记录
	- 层表------层0
	- 块表------`*MODEL_SPACE`、`*PAPER_SPACE`、`*PAPER_SPACE0`
	- 线型表----CONTINUOUS、BY_LAYER、BY_BLOCK
	- 注册应用程序表-----ACAD
	- 文字样式表-----STANDARD
- 有名对象字典，包含Group和Mline样式两个字典，Mline样式字典中总会有Standard样式
- 其他的非数据库对象

### 1.2 数据库的创建与生成

DatabaseServices命名空间中的Database类表示图形数据库

```csharp
public Database(bool buildDefaultDrawing, bool noDocument)
```

第一个参数表示是否要创建一个空的图形数据库对象，为true时会生成数据库最基本的数据，及数据库的初始状态。当为false时，新创建的图形数据库对象完全为空，可以通过读入一个Dwg文件来生成其数据。
第二个参数为true时，新创建的图形数据库不会关联到当前文档。

不能用Dispose函数销毁由HostApplicationServices.WorkingDatabase返回的当前数据库对象。

### 1.3 图形数据库的保存

要保存一个图形数据库，可以使用Database类的SaveAs函数
```csharp
public void SaveAs(string fileName, DwgVersion version)
```
保存的文件名和要保存的CAD版本。后者是一个枚举类，用current表示当前版本

### 1.4 读取外部文件

Database类的ReadDwgFile函数可以将外部Dwg文件读入到新创建的图形数据库对象中，函数如下
```csharp
public void ReadDwgFile(string fileName, FileShare fileSharing, bool allowCPConversion, string password)
```
fileName要求要读入的带完整路径的Dwg文件的文件名
fileSharing表示当fileName文件被打开时，其他程序可以怎么访问它，是一个System.IO.FileShare类型的枚举，CAD只支持Read、ReadWrite和Write三种取值。
allowCPConversion控制读入一个与系统编码不同的文件时的转化操作，如在英文操作系统中读入一个中文Dwg文件，如果设置为false，那么CAD会弹出一个对话框显示有关的信息并询问用户是否允许一些默认的转换操作，可能会导致一些数据丢失。设置为true则是直接进行转换操作
password表示要读入的文件密码，如果没有密码，设置为null或者空字符串。

### 1.5 局部加载

要实现Dwg文件的局部加载，应该在调用ReadDwgFile函数之后执行Database类的ApplyPartialOpenFilters函数，最后还要执行Database类的CloseInput函数关闭文件的输入。
```csharp
public void ApplyPartialOpenFilters(SpatialFilter spatialFilter, LayerFilter layerFilter)
```

其中，spatialFilter参数指定了在模型空间中的一个区域内进行范围过滤，layerFilter参数指定需要进行过滤的图层。

SpatialFilter和LayerFilter 均属于DatabaseServices.Filters命名空间。

## 2. 在图形数据库之间传递数据

在CAD中，可以通过复制粘贴的方式在不同的Dwg文件中交换数据。但是在.NET编程的角度看，由于不同的图形数据之间是相互独立的，因此不能通过上述方式传递数据。

### 2.1 Wblock操作

在CAD中，Wblock命令用于将对象保存到文件或将块转换成文件。

![](../pic/Pasted%20image%2020260508140821.png)

### 2.2 Wblock函数

Database类提供了Wblock函数来实现从一个已存在的图形数据库创建一个新的图形数据库。或者把一个图形数据库中指定的实体复制到另一个图形数据库中。

Wblock函数有四种构造函数
- `public Database Wblock()`
- `public Database Wblock(ObjectId blockId)`
- `public Database Wblock(ObjectIdCollection outObjIds, Point3d basePoint)`
- `public Database Wblock(Database outputDataBase, ObjectIdCollection outObjIds, Point3d basePoint, DuplicateRecordCloning cloning)`

>Wblock函数会创建一个新的图形数据库并分配内存，在使用结束后，必须手工销毁图形数据库

### 2.3 插入数据库

Database类的Insert函数可以把一个图形数据库复制到另一个图形数据库。
- 源数据库中有名对象字典的应用程序定义的对象不会被复制。
- 如果源数据库中的对象与目标数据库中的对象有冲突，如拥有相同的线型，则CAD保持目标数据库中的对象不变。

```csharp
public ObjectId Insert(string blockName, Database dataBase, bool retain)
```
该函数将源数据库模型空间中的实体复制到目标数据库中指定的块表记录中，这个块表记录在目标数据库中被新建并把它的ObjectId返回。

```csharp
public ObjectId Insert(Matrix3d transform, Database dataBase, bool retain)
```
该函数将源数据模型空间中的实体复制到目标数据库的当前空间（模型空间或图纸空间）中，同时对这些实体进行指定的变形操作（transform）

```csharp
public ObjectId Insert(string destinationBlockName, string sourceBlockName, Database dataBase, bool retain)
```
该函数将源数据库中一个有名块表记录中的实体复制到目标数据库中指定的有名块表记录中，如果目标数据库中没有destinationBlockName的块表记录，则会创建该块表记录，如果有destinationBlockName的块表记录，则由源数据库中的块表记录取代它。

## 4. 文档管理

### 4.1 什么是文档 Document

- 文档是cad软件界面上每一个打开的.dwg图形文件在内存中的数字化代理。
- 连接着UI界面和底层数据
- 主要包含了数据库、编辑器和图形屏幕三个核心要素
	- 数据库是负责存储持久化数据
	- 编辑器负责与用户交互
	- 图形屏幕负责渲染该文档的视觉表现
- 综合来说，文档像一个运行环境 context

### 4.2 Document 在内存模型中的位置

在 AutoCAD 这种多文档界面（MDI/Multiple Document Interface）架构中，层级结构如下：

- **Application (应用程序):** 整个 CAD 进程。
    
- **DocumentCollection (文档集合):** 管理当前所有打开的文档。
    
- **Document (当前文档):** 你正在操作的那一个实例。
    
- **Database (数据库):** 文档里存储的非可视化与可视化数据。

### 4.3 与文档操作有关的类

.NET中的DocumentCollection、Document和Database类用来对图形文档进行操作

| 文档操作 | .NET 类             | 涉及的函数                                 |
| ---- | ------------------ | ------------------------------------- |
| 新建   | DocumentCollection | Add                                   |
| 打开   | DocumentCollection | Open                                  |
| 保存   | Database           | SaveAs                                |
| 关闭   | Document           | CloseAndDiscard（不保存）、CloseAndSave（保存） |
| 锁定   | Document           | LockDocument                          |
| 置为当前 | DocumentCollection | MdiActiveDocument（为属性）                |
> DocumentCollection类的CloseAll可以关闭所有打开的文档。

### 4.4 文档的锁定与解锁

在CAD中修改对象时往往会与一些其他的操作发生冲突，这可能会导致CAD发生错误甚至导致崩溃。解决办法是在修改对象时锁定要操作的文档。

以下操作必须进行文档锁定。
- 在无模式对话框中与CAD进行交互
- 访问打开的非当前文档
- 程序作为COM服务器
- CommandFlags.Session标识的命令

Document类的LockDocument函数用来对文档进行锁定，该函数会返回一个DocumentLock对象。当对锁定文档中的实体修改完毕后，必须将文档解锁，可以通过DocumentLock对象的Dispose函数实现。可以使用using语句自动解锁。

## 5. 外部参照与光栅图像

### 5.1 外部参照

外部参照（Xref，External Reference）是把一个外部 DWG 文件链接到当前图形中。

- **与块的相似点**：Xref 在图形中也显示为块表记录中的一个块定义（BlockTableRecord），插入后的实例也是 BlockReference
- **与块的不同点**：块的数据是复制进当前数据库的；Xref 的数据来自外部文件，只是"引用"。外部文件更新后，当前图形的 Xref 也会跟着变化
- **路径类型**：完整路径、相对路径、无路径（搜索 AutoCAD 支持文件搜索路径）
- **嵌套 Xref**：Xref 里还可以引用其他 Xref，形成树状结构

关键属性：
- `BlockTableRecord.IsFromExternalReference` 判断块表记录是否是 Xref
- `BlockTableRecord.PathName` 获取外部参照文件路径
- `Database.ResolveXrefs` 解析未解决的 Xref 引用

Xref 的一个重要后果是图层的改名：Xref 文件的图层在当前图形中会变成 `XrefName|LayerName` 的格式（竖线分隔），这个特点是判断一个实体是否来源于 Xref 的常用方法。

### 5.2 光栅图像

光栅图像（Raster Image）与 Xref 类似但引用的是图片文件（PNG、JPG、TIFF 等）。核心类是 `RasterImage`，存储在 `RasterImageDef` 字典中。与 Xref 不同，光栅图像是栅格数据而非矢量数据，不能像 Xref 那样对其中的实体进行对象捕捉。
