CAD中事件的三种类型
- 应用程序事件
	- 在CAD应用程序及其环境更改时被触发，如打开图形，创建新图形，CAD命令执行，系统变量的更改等，与具体的对象和文档无关
- 文档事件
	- 这类事件与特定的文档有关，可以响应文档内容的更改。
	- 可以响应对象的添加、删除或修改
	- 快捷键的激活
	- 优先选择集的更改
	- 图形窗口的更改和图形的重生成
	- 等等
- 对象事件。特定对象的修改

CAD捕获到某个事件之后，会执行事件处理程序，事件中包含的信息会通过参数传递给事件处理程序。

进行处理时要遵循一定的原则
- 不要依赖事件发生的顺序 / 操作的顺序
	- **理解：** 计算机处理事件极快，且 CAD 内部逻辑复杂。你不能假设“修改图纸”事件一定在“保存”事件之前完成。
	- **开发建议：** 代码逻辑要独立。不要写“如果 A 事件先发生就做 X，B 先发生就做 Y”的代码，因为这个顺序在不同版本或复杂场景下不可靠。
- 不要从事件处理程序中执行交互式函数 / 启动对话框
	- **理解：** 事件触发时，CAD 正忙着处理数据库的变更。如果你此时弹出一个对话框让用户点（交互），或者强行让用户在屏幕上选个点，会打断 CAD 原有的执行流。
	- **后果：** 极易导致 CAD 锁死（死机）或报 `eInvalidInput` 错误。
- 可以写数据，但发出事件的对象除外
	- **理解**：比如在监听“圆的半径变了”这个事件。当事件触发时，你可以去改这条线的颜色，但千万不要在这个事件里去改这个圆的半径。
	- **后果：** 会导致“改半径 -> 触发事件 -> 又改半径 -> 又触发事件”的**无限递归**，瞬间撑爆内存。
- 不要执行任何触发相同事件的操作
	- **理解：** 这是上一条的扩展。如果代码是在“对象被修改”时运行，那么在代码里就不要执行任何会引起“对象被修改”的操作。
	- **后果：** 避免死循环
-  模式对话框不触发事件
	- **理解：** 模式对话框下，不能操作后面的界面，因此不会触发事件
	- **开发意义：** 事件监听代码在用户打开“另存为”或“选项”窗口期间是“休息”的，不要指望在这期间抓取到任何操作。

在处理 CAD 事件时，要保持“只看不动”或者“延后行动”的心态：

## 1. 应用程序及文档事件

### 1.1 常用的应用程序事件

下表是常用的应用程序事件，都是ApplicationServices.Application类的静态成员。

|     事件名     |                              类名/类型                               |
| :---------: | :--------------------------------------------------------------: |
| AutoCAD 将关闭 |                  `BeginQuit`<br>`EventHandler`                   |
|  显示自定义对话框   |    `DisplayingCustomizeDialog`<br>`TabbedDialogEventHandler`     |
|  显示草图设置对话框  | `DisplayingDraftingSettingsDialog`<br>`TabbedDialogEventHandler` |
|   显示选项对话框   |      `DisplayingOptionDialog`<br>`TabbedDialogEventHandler`      |
|  系统变量值已改变   |  `SystemVariableChanged`<br>`SystemVariableChangedEventHandler`  |
|  系统变量值将改变   | `SystemVariableChanging`<br>`SystemVariableChangedEventHandler`  |
>应用程序事件在CAD关闭或事件被注销之前，是一直存在的

### 1.2 常用的文档事件

下表是常用的文档事件，都是ApplicationServices.Document类的事件成员

| 事件名    | 类 / 类型                                                   |
| ------ | -------------------------------------------------------- |
| 文档开始关闭 | BeginDocumentClose<br><br>DocumentBeginCloseEventHandler |
| 命令被取消  | CommandCancelled<br><br>CommandEventHandler              |
| 命令结束   | CommandEnded<br><br>CommandEventHandler                  |
| 命令执行失败 | CommandFailed<br><br>CommandEventHandler                 |
| 命令开始   | CommandWillStart<br><br>CommandEventHandler              |
>如果文档被关闭，则与之关联的文档事件将不复存在

### 1.3 常用的文档集合事件

文档集合事件用来响应CAD程序中打开的所有文档，下表是常用的文档集合事件，是ApplicationServices.DocumentCollection成员

| 事件名    | 类/类型                                                                   |
| :----- | :--------------------------------------------------------------------- |
| 文档被激活  | `DocumentActivated`<br><br>`DocumentCollectionEventHandler`            |
| 文档被创建  | `DocumentCreated`<br><br>`DocumentCollectionEventHandler`              |
| 文档被关闭  | `DocumentDestroyed`<br><br>`DocumentDestroyedEventHandler`             |
| 文档锁定改变 | `DocumentLockModeChanged`<br><br>`DocumentLockModeChangedEventHandler` |

>文档集合事件在CAD关闭或事件被注销之前，是一直存在的

### 1.4 处理.NET中的CAD事件

- 创建事件处理函数 `Application_BeginQuit(object sender, EventArgs e)`
- 把事件处理函数与事件联系起来
	- 使用加法赋值运算符 +=
		- `Application.BeginQuit += new EventHandler(Application_BeginQuit);`
		- `Application.BeginQuit += Application_BeginQuit;`
	- 使用匿名方法
		- `Application.BeginQuit += delegate(object sender, EventArgs e){具体实现};`
	- 使用lambda表达式
		- `Application.BeginQuit += (object sender, EventArgs e)=>{};`
- 注销事件处理函数，通过减法赋值运算符实现 -=

## 2. 对象事件

### 2.1 两种类型的对象事件

CAD中的对象事件用来响应图形中对象的打开、添加、修改和删除动作。该事件可以分为两种类型：对象层和数据库层。
- 对象层的对象事件对应于图形数据库中的一个对象
- 数据库层的对象事件则对应于图形中的所有对象

### 2.2 常用数据库层的对象事件
下表是常用的数据库层的对象事件，都是DatabaseServices.Database成员

| 事件名     | 类/类型                                                |
| :------ | :-------------------------------------------------- |
| 添加实体    | `ObjectAppended`<br><br>`ObjectEventHandler`        |
| 删除实体    | `ObjectErased`<br><br>`ObjectErasedEventHandler`    |
| 打开以修改实体 | `ObjectOpenedForModify`<br><br>`ObjectEventHandler` |
| 修改实体    | `ObjectModified`<br><br>`ObjectEventHandler`        |

### 2.3 对象事件与文档事件的关联

对象事件一般与文档事件相关联，如果在CAD图形中移动了一个圆，将依次触发以下事件
- 文档事件 CommandWillStart
- 对象事件 ObjectOpenedForModify
- 对象事件 ObjectModified
- 文档事件 CommandEnded
