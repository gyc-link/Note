## 坡口（坡切）

### 内缩方向 / 整圆（2026.9）

目前程序的偏移方向是符合右手定则的，仅偏移直线和圆弧两种。如果是圆弧，则是通过改变圆的半径实现的偏移，所以有两层判断：
1. 判断是否是逆时针
2. 判断圆的法线

原本的两层判断：
1. 判断是否是逆时针，如果是逆时针，就不改变偏移值的正负
2. 判断法向是否为 z 轴，如果是，就减小圆弧的半径，反之，增大圆弧的半径

但是对于整圆来说，就目前的算法，第一步判断永远是逆时针（仅靠下一条线的起点是否是当前线的终点，而整圆只有一条线、一个顶点）。

- 一个轮廓（`loop`）可能由多条曲线组成；
- 某些曲线有坡口信息，有 `Setback`；
- 但是当前这个场景是"只有一条曲线的轮廓"；
- 你取的是"这个单曲线轮廓对应的偏移值"。

将所有拿到的圆弧都转成逆时针，然后针对只有一根曲线的情况，在不是外环的时候，反转这个曲线。

问题变化：由不生效 -> 方向不正确

鞋带公式：输入的是顶点，得到的是面积。

这次问题的本质是坡口内缩方向不正确，发生的情况是整个轮廓线只由整圆构成。

原因：其他情况能正常处理的原因是轮廓线在构建成环的时候，依靠顶点顺序逆时针成环，所以后续的偏移处理只要按照右手定则就能正确处理，而整圆是否是逆时针需要靠本身 curve3d 的法向确定，没法依靠顶点顺序去判断，源程序处理时默认把输入的整圆当成逆时针处理。

解决方法：应该从源头解决，统一在成环的时候都是逆时针，并提供反转成顺时针的接口，而不是简单当成特殊情况处理。

## 排版图

### 面域 vs 轮廓线（2026.8 总结）

目前生成主件/小件排版图：
1. 没有面域处理文字的，不在面域上 copy 一份原轮廓线（修订云线图层），默认面域生成成功。
2. 用户可设置是否生成修订云线的原轮廓线。
3. 当指定了坡口绑定数据后：轮廓线不再使用面域，而是使用其边；将每个要开坡口的边和坡口文字绑定成一个组；将面域放置到参考图层。

生成主件/小件排版图时，如果没有开坡口，那么是生成的面域，而不是轮廓线；但是如果开了坡口，面域将被移动到其他图层。

现在问题是，有时候排版图中有面域，有时候排版图中没有面域。排版图中的内容总共就这么多，这种不一致，谁说了算。功能的描述是将板件零件的轮廓线修改成面域，并增加零件标号标识；但是，如果开了坡口，面域移动到其他图层，并且出排版图的图层里是轮廓线。

思路1：该生成排版图逻辑，统一生成轮廓线？感觉不是很现实，如果改成生成轮廓线，那么一开始生成面域的意义是什么？为了计算面积吗？
思路2：将没有轮廓线的排版图进行炸开操作，再去计算轮廓线的包围盒，跟直接用面域好像多了一点计算。

升级 filter 函数，生成的排版图里没有轮廓线只有面域：
1. 可以 filter 函数中，将这些面域炸开，得到轮廓线
2. 生成排版图时就统一一下，轮廓线、面域放到其他图层，或者干脆不要面域。

原功能业务规则：修改零件的轮廓线为面域。更新配料表依赖于这个结果。新需求因为开坡口的原因，面域不适用，因此结果直接改变了，变成轮廓线+移动了图层的面域。

寻找排版图（直觉上，就是挨在一起的那堆实体）依据"轮廓线+面域"的包围框过滤出来。

排版图如果有面域的话，用面积最大+周长跟轮廓线在容差范围内相等这个条件。

### 寻找排版图 / 包围盒（2026.8 总结）

根据包围盒的连接情况寻找排版图。设置一个字典，key 是合并之后的包围盒，value 是合并之前的所有包围盒。

怎么合并？根据包围盒的连接情况，如果连接了，就进行合并。
1. 判断下一个包围盒是否跟"正在合并的包围盒"连接或者相交。如果不相交，将这个包围盒作为后续的需要合并的包围盒，接着判断下一个包围盒跟正在合并的包围盒之间的关系。
2. 如果相交，判断该包围盒是否跟"正在合并的包围盒"的子包围盒有相交，如果有，进行合并；如果没有，认为该包围盒是下一个需要合并的包围盒，因为该包围盒不直接与正在合并的包围盒产生任何连接。

将该算法再执行一次，这次"正在合并的包围盒子集里只有他一个"，就可以将之前包含在内但不合并的包围盒合并。

组孔标注的操作是框选要处理的螺栓孔和轮廓线，组孔标注的结果是经过修改的。

解决方案：弄清楚用户的真实需求，弄清楚这两个功能的差异。如果确实是两个完全不同的功能，那么用户的需求是不是把这两个功能合并？还是当时沟通时就是希望将这两个功能分开？

问题32（练习）：
- 需求：用户遇到的一种螺栓孔阵列形式，程序的组孔标注功能没有效果，且程序没有异常。
- 我目前理解：组孔标注功能不支持标注用户遇到的那种螺栓孔排布形式。
- 已知事实：验证了多种螺栓孔的排布：①对于阵列排布的螺栓孔，标注能够生效，即行距、列距一致的螺栓孔；②将阵列排布的螺栓孔进行镜像后，标注有时也能生效；③间距不一致的螺栓孔排布大概率出问题。
- 我的猜测：应该是跟螺栓孔的排布方式有关。
- 我要验证：看代码中是怎么识别出一组螺栓孔的，如果间距特别大，是不是会被分为两组。
- 原因：因为目前的代码中，并没有出现错误，而是进行到某处，代码识别到了并返回空值，导致后面标注的对象也是空，所以没有成功标注。

目前问题发生在，如果组孔的间隔不一致，导致 IsCellGroup 函数分组返回的 cell 是 null 值。这个函数接收一个动态数组，里面的元素是已经根据组孔的连接情况进行分组了的（这个连接也比较宽泛，就是离得远于某一个值的时候）。返回一个二维数组，猜测是根据螺栓孔的空间排布，比如阵列排列的螺栓孔，这个二维数组代表螺栓孔的空间排布。

交错螺栓排列 interlaced Bolt pattern：

```
【普通矩阵 Grid】          【交错矩阵 Interlaced】
  (Row 1)  O   O   O        (Row 1)  O       O       O
  (Row 2)  O   O   O        (Row 2)      O       O       O  <-- 错开半个间距 (Staggered)
  (Row 3)  O   O   O        (Row 3)  O       O       O
```

比较符合工程的螺栓孔排布？

有一个参数是控制程序识别出两组螺栓孔的，这个参数不能动。

如果将螺栓孔提前分组，会生成多的标注：一个是中心到靠近边界的标注，一个是到两侧的标注。这是将本来是一组的螺栓孔强行分成了几部分，会多出来的标注。如果不强行分组，原本的程序是处理不了不等间距的螺栓孔排布的。

识别非均匀行距、均匀列距的二维点阵子阵列集合。算法：遍历二维点阵的行索引序列，计算相邻行之间的间距，如果一处索引的相邻行间距相同，则将上一处索引、该索引和下一处索引都加入当前的子阵列集合中；如果不相等，认为均匀区域结束，新建另一个子阵列集合，继续寻找。最终得到多个子阵列集合，可能包含空的集合。

1、过滤空集合：如果所有集合均为空，则不存在均匀行距子阵列；按索引顺序，两两分组。
2、过滤后的结果，行索引是否完整覆盖所有索引：如果完整覆盖，说明原二维点阵由多个均匀行距子阵列拼接组成，分组成功；如果没有完整覆盖，进入步骤三。
3、找出未被任何子阵列包含的行索引：对每个未覆盖行索引，取其前一个相邻行索引与当前行索引组成一组；取其后一个相邻行索引与当前行索引组成一组；额外处理一下第一个和最后一个；将这些补充组加入最终结果。分组结束。
