# 为什么能唯一确定算术表达式的二叉树？

## 问题

给定表达式 `a + b * (c - d) - e / f`，为什么能画出**唯一**一棵二叉树，而不是多棵？

## 答案

因为算术表达式有三条规则，联合保证了**解析的唯一性**（无二义文法）：

### 1. 括号优先级最高（Parentheses）

`(c - d)` 被括号强制包裹，**必须先**构成一棵子树。没有任何其他解析方式可以把 `c` 和 `d` 分开。

### 2. 运算符优先级（Operator Precedence）

`*` 和 `/` 的优先级高于 `+` 和 `-`。这意味着：

- `b * (c-d)` → `*` 会把 `b` 和 `(c-d)` 牢牢绑在一起，形成子树
- `e / f` → `/` 会把 `e` 和 `f` 绑在一起，形成子树

优先级规则阻止了 `a + b` 被错误地当成 `*` 的右操作数。

### 3. 左结合性（Left Associativity）

`+` 和 `-` 优先级相同，结合方向是**从左到右**。所以：

```
a + b*(c-d) - e/f   →   (a + b*(c-d)) - e/f
```

而不是 `a + (b*(c-d) - e/f)`。

如果 `+` 和 `-` 是右结合的，树的结构就会不同。

---

## 形式化：运算符优先级文法（Operator-Precedence Grammar）

这棵树的唯一性来源于编译原理中的 **运算符优先级文法**：

| 规则 | 说明 |
|------|------|
| 终结符 | `a b c d e f + - * / ( )` |
| 优先级关系 | `⋖`（左优先）、`⋗`（右优先）、`≐`（相等）|

对于我们的表达式，优先级表如下：

| 运算符 | 优先级 |
|--------|--------|
| `( )` | 最高 |
| `* /` | 中 |
| `+ -` | 低 |

解析算法（如 **Pratt Parser** 或 **Shunting-Yard**）按优先级比较，每次把优先级最高、位置最左的运算符作为当前子树的根，从而构造出唯一的二叉树。

---

## 如果规则不同，树就不同

假设有一条反直觉的规则："`+` 优先级高于 `*`"，那么同一表达式 `a + b * c` 会解析成：

```
    *          而不是标准的      +
   / \                        / \
  +   c                      a   *
 / \                            / \
a   b                          b   c
（非标准解析）                （标准解析）
```

---

## 总结

| 机制 | 作用 |
|------|------|
| 括号 | 强制子树边界 |
| 优先级 | 决定运算符的结合紧密程度 |
| 左结合性 | 同级运算符从左到右归约 |

三者共同构成一个 **无二义性上下文无关文法（Unambiguous CFG）**，使得每一条合法算术表达式都能画出**唯一**一棵二叉树。

## 对应二叉树

```
          −
        /   \
       +     ÷
      / \   / \
     a   * e   f
        / \
       b   −
          / \
         c   d
```

表达式：`((a + (b * (c - d))) - (e / f))`
