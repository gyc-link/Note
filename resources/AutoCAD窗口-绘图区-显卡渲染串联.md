# AutoCAD 的窗口、绘图区、显卡是怎么串起来的

你打开 AutoCAD，画了一条线。这条线怎么从"你点了一下鼠标"变成"屏幕上出现一条线"？

整个过程有四层，从外到内说。

---

## 第一层：窗口（壳）

AutoCAD 启动后，你看到的是一个 Windows 窗口。有标题栏、菜单栏、工具栏、状态栏。这个窗口就是一个容器，跟记事本的窗口没本质区别——都是操作系统给的一块矩形区域，程序可以往里面画东西。

窗口本身不负责显示图形。它只是"画布框"。

## 第二层：绘图区（画布）

窗口中间那块黑色的区域，就是绘图区。这是 AutoCAD 自己创建的一个子窗口（准确地说，是一个自定义控件），专门用来显示你的图纸。

绘图区做的事情：

-   接收鼠标和键盘事件（点击、拖拽、滚轮缩放）
-   维护一个"相机"——当前从哪个角度、多远的地方看模型
-   把"模型里有什么"交给下一层去画

你可以把绘图区理解成一个导演。它知道场景里有什么（模型数据），知道摄像机在哪（视图），但它不自己画——它喊"显卡，干活"。

## 第三层：显卡渲染（画笔）

这才是真正"画"的地方。

显卡（GPU）跟 CPU 的区别：CPU 是一个数学教授，什么都能算但一次只能算一件事；GPU 是上千个小学生，每人只会做简单算术，但一千个人同时做。

画图这件事恰好就是"一千个简单任务同时做"——屏幕上每一个像素的颜色，跟它旁边的像素没依赖关系。所以 GPU 特别适合干这个。

AutoCAD 通过 DirectX（Windows 上的图形 API）把画图指令发给显卡：

1.  AutoCAD 把模型数据（线、圆弧、曲面）切成三角形。任何图形都可以用足够多的小三角形近似
2.  这些三角形数据打包发到显存
3.  GPU 的顶点处理器算出每个三角形顶点在屏幕上的位置
4.  GPU 的光栅化器把三角形变成像素
5.  GPU 的像素着色器给每个像素涂颜色
6.  结果写到显存里的帧缓冲区
7.  显示器从帧缓冲区读数据，显示到屏幕上

整个过程每秒发生 30 到 60 次。每次叫一帧。

## 第四层：中间有个"翻译官"——显示列表

AutoCAD 不是每一帧都重新分析你的 dwg 文件的。那太慢了。

它维护一个叫"显示列表"的东西，可以理解为"画图指令缓存"。模型里这条线是红色的、宽度 0.5、从 (0,0) 到 (100,50)，这些指令在显示列表里存好了。

-   **REGEN（重生成）**：重新读 dwg 数据，重建显示列表。慢，但精确。比如你把圆放大很多倍，原来用 32 条边近似的圆现在看着有棱角了，REGEN 会用更多边重新近似。
-   **REDRAW（重绘）**：直接用现有的显示列表重新渲染一次。快，但精度不变。比如你拖了一个窗口挡住 AutoCAD，移开后它只需要 REDRAW。

这就是为什么有时候 AutoCAD 提示"输入 REGEN"——显示列表里的数据不够精确了，需要重建。

## 整条链路串起来

```
dwg 文件 → CPU 解析 → 模型数据 → 显示列表（CPU 整理、切三角形）
    → DirectX 指令 → 显卡驱动 → 显存 → GPU 顶点处理
    → GPU 光栅化 → GPU 像素着色 → 帧缓冲区 → 显示器
```

你缩放、旋转视图的时候，AutoCAD 并不改模型数据——只改了绘图区里那个"相机"的位置，然后重新发一批画图指令给显卡。模型没动，只是视角变了。

你编辑图形的时候（比如延长一条线），AutoCAD 改模型数据，然后更新显示列表里对应那部分，再让显卡重新渲染那一帧。

## 硬件加速到底是什么

AutoCAD 里有个设置叫硬件加速（`GFXCONFIG` 命令可以开关）。

-   **开着**：上面说的那套流程——三角形变换、光栅化、着色——全在 GPU 上跑。快。
-   **关着**：这些活全让 CPU 干。CPU 用软件模拟 GPU 的工作，叫"软件渲染"。慢很多，但兼容性好——有些显卡驱动有 bug，关了反而不出错。

所以如果你画图很卡，先看硬件加速开了没。如果开了还卡，是模型太复杂（三角形太多），GPU 算不过来了。

## 一个常见的误解

你可能会想：AutoCAD 画的是矢量图（线、圆、弧），不是像素图啊？为什么还要切三角形？

屏幕上显示的一切最终都是像素。你的显示器就是 1920×1080（或更高）个彩色小点，没有"线"这种东西——只有像素排列成线的形状。

AutoCAD 的 dwg 文件存的确实是矢量数据（数学公式描述的线、圆、弧），但显示这个环节，必须把矢量转成像素。这个转换就是 GPU 干的，中间那步"切三角形"是因为 GPU 只会处理三角形——它是为 3D 游戏设计的，只会这一招，但这一招特别快。
