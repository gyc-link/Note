1、多段线重复顶点与退化线段
多段线如果存在**重复顶点**，那么 `GetLineSegmentAt()` 仍然可能返回一个线段对象，但这条线段实际上是**退化线段**（degenerate segment），其长度为 `0`。
处理思路：
- 最好在数据源头就删掉重复顶点
- 如果源头不能保证干净，就在程序里主动过滤掉长度为 `0` 的线段
这说明：
> API 能返回“线段对象”，不代表这条线段在几何上是有效的正常线段。

2、分割线处理
分割线在参与后续计算前，最好先做两件事：
- 按顺序排好
- 编号
这样后面无论是做连接、遍历、构边界，还是调试，都会清楚很多。
本质上是先把“杂乱的几何片段”整理成“有序的数据”。

3、叉乘的理解
叉乘严格来说是定义在 **3D** 里的。
不过在平面几何里，常用的是它的“二维简化形式”：
- 把二维向量看成 `z = 0` 的三维向量
- 叉乘后只关心 `z` 分量的正负
所以平时说：
- 点在边的左边
- 点在边的右边 
本质上还是在用**三维叉乘的 z 分量符号**做判断。

4、冒泡排序
冒泡排序更准确地说是：
- 每一趟通过**两两比较交换**
- 把当前范围内的**最大值**放到末尾
- 所以每一趟确定的是“最后一个位置”的正确值

数学层
- 两条直线求交点
- 点是否在线段上
- 求一段圆弧长度
- 叉乘判断点在边的左边还是右边
只看几何定义。只要数据给齐，脱离 AutoCAD 图形界面也能算。

图元层
- 打开一条 `Polyline`
- 读它的图层、颜色、ObjectId
- 把它加入数据库
- 事务里修改它
这层关心“图里那个对象”。不是纯数学，是“DWG 里的对象管理”。

第三层：编辑器识别层
- 用户点一个内部点，让系统自动找包围它的边界
- 用户窗口选择，系统按过滤器和可见状态返回对象
- 填充时系统自动判断哪些对象共同构成闭合边界
- 小缝要不要忽略，岛洞算不算边界
这层已经不是单个对象的几何属性了，而是**命令规则 + 当前绘图环境 + 一组图元的综合解释**。

以后判断“该用哪层 API”，可以问自己三个问题
1. 我的问题里，边界/对象是不是已经明确给我了？  
如果已经明确，通常先想几何。

2. 我是不是在处理图纸里的对象管理？  
比如图层、事务、追加到数据库、删除、复制，那就是数据库图元层。

3. 我是不是在让 CAD 按命令习惯帮我“识别”某个结果？  
比如自动找边界、选择、填充、从视图里理解区域，那就是编辑器识别层。几何计算 + 图元组织 + 编辑器识别规则
