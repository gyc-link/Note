若按精确几何考虑，交点重复主要可能来自相邻线段共享顶点；但在浮点计算与容差判定下，重复的定义变成"==落在容差范围内的近点=="，
因此重复不一定只发生在相邻段之间，==去重策略不能只依赖局部拓扑关系，而应以整体结果集的容差判等为准。==

因为实体类内部保存了几何信息，所以可以根据这些信息构造出对应的几何类对象，用于计算和分析。分层本质上就是把图元拆成"形状本身"和"系统管理信息"两部分。前者用于几何计算，后者用于数据库存储、显示和编辑管理。

对于==逆时针排序==的凸多边形，依次判断点相对于每条边的位置。若点始终位于所有边的==左==侧，则点在多边形内部；若某次落在右侧，则点在外部。若叉乘结果为 0，还需继续判断该点是否在线段范围内，以区分边界情况。

对于一般简单多边形，可使用射线法：从待测点沿固定方向作射线，统计其与多边形边的交点数，奇数表示在内部，偶数表示在外部。实现时需先单独判断点是否落在边上，需要注意顶点被重复计数的问题。

GetClosestPointTo（）curve下的虚方法，extend参数决定在搜寻过程时是否扩展曲线，对于不同类型的，直线两端扩展，沿着同圆心，同半径的圆周无限延伸，多段线根据每段的类型进行扩展

两两比较，符合条件就删除，但是是从==集合的尾部删除==
```csharp
static void FilterEqualPoints(Point3dCollection points, double tol)
{
	for (int i = points.Count - 1; i > 0; i--)
	{
		for (int j = 0; j < i; j++)
		{
			if (IsEqual(points[i], points[j], tol))
			{
				points.RemoveAt(i);
				break;
			}
		}
	}
}
```

内存循环平均情况下走不到j=i，用了break处理
比较次数最坏情况是n^2
removeat最坏情况也是n^2

最近点太靠近射线起点，导致 API 在带容差的几何判断里，把一个本该在后方的点误报成了前方交点。

书上的思路是从多段线上找一个离给定点（要判断的点）最近的点，射线基点是给定点，方向是最近点到给定点，因此，如果射线与多段线有相交的情况，那么交点应该都是在射线的==正方向==上。
