## out，ref，param ref return

输出参数out，
实参需要是变量，不能是表达式，得有个地方放参数的返回值，
在方法内部，需要在给输出参数赋值之后才能读取它，所以没必要在实参的时候就给它赋值，
在方法内部，每条可能得路径都必须给输出参数赋值，跟return一样
新功能：可以在方法调用的时候加入变量类型的声明。且==脱离方法后依旧可用==

方法的输出参数`out`意思是：这个参数主要是“==由方法负责赋值后带出来==”,传进去前可以不初始化,方法内部必须赋值后才能返回,重点是“输出结果”

参数数组 params
1、必须在最后
2、参数列表中，只能有一个参数数组。
3、调用的时候不加params关键字
`params` 的本质是：

> **一种让方法支持可变数量参数的语法糖，底层仍然是数组参数。**

![](../pic/Pasted%20image%2020260413174500.png)

引用参数`ref`：
- 调用前，实参**必须已经赋值**
- 方法里可以改，也可以不改
- 总结：方法的引用参数`ref`意思是：方法直接操作调用者手里的那个变量本身，因此传进去前必须已经初始化，方法里可以读也可以改，重点是“共享同一个变量”

**ref返回功能**  ==把“变量本身”传回来，而不是把变量里的值传回来。==因此对任意一个变量的改动都会反应到另一个变量上，例如ref int x = ref y
同样使用时，方法前和return里都要加上ref关键字
如：ref int func（ref int x）{return ref x}

ref int func（int x）{return ref x}不行
因为这里的 `x` 是普通值传递参数。
- 调用时把外部变量的值复制给了 `x`
- `x` 只是方法内部自己的一个局部变量
- 方法结束后，这个 `x` 就没意义了
所以不能把它 `ref return` 出去。
否则就相当于：
返回一个指向“方法内部临时变量”的引用
这是不安全的，编译器不允许。==把本该消失的东西“带出去”了==

限制：
- 不能返回局部变量
- 不能返回临时值的
- 不能把生命周期不够长的东西引用返回出去
- 更具体的要求
- 调用方如果要接成引用，也要写 `ref`


记住
==引用类型默认传参 = 按值传递引用。==
