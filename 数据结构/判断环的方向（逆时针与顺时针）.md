## 引入：为什么要判断环的方向？

做完 [[半边数据结构]] 后你有了"环 (Loop)"的概念——一个面由一串半边首尾相接围成。但在 CAD 拓扑里，光知道"这是一个环"还不够，经常要回答：

> 这个环是**逆时针 (CCW)** 还是**顺时针 (CW)**？

比如：

- **面积/法线**：逆时针环的有向面积是正，顺时针是负，直接决定面的朝向。
- **内环 vs 外环**：一个面上挖洞，外轮廓和内洞的方向约定相反。
- **偏移/抽壳**：沿着"外侧"还是"内侧"偏移，先得知道哪边是内侧。

本文对应真实代码 `model/TModel.cs` 里的两个函数：

| 函数 | 作用 |
|:---|:---|
| `GetAnticlockwiseLoops()` | 筛选器：吐出所有逆时针环 |
| `IsAnticlockwise(TLoop)` | 核心：判断单个环是逆时针还是顺时针 |

---

## 核心思想（先记住一句话）

> 沿着环的行走方向走，朝**左手边**偏移一小步，落点在环**内部** → 逆时针；在**外部** → 顺时针。

这是几何里的固定事实：

| 环的方向 | 沿着行走方向，内部在哪边 |
|:---|:---|
| 逆时针 CCW | **左手边（左侧）** |
| 顺时针 CW | 右手边（右侧），左侧是外部 |

```
逆时针环                       顺时针环
    ↑ ← 行走                       ↓ → 行走
   ┌─────┐                       ┌─────┐
   │     │   左手边 = 内部        │     │   左手边 = 外部
   └─────┘                       └─────┘
```

所以整段代码只做两件事：

1. 造出"左侧那一点"（代码里叫 `testP`）
2. 用**射线法**判断 `testP` 在环内还是环外

> [!NOTE] 和你已有知识的连接
> 判断方向这件事，纯直线多边形其实有更直接的写法：对每条边累加**叉乘**（有向面积，鞋带公式），符号正负就是逆/顺时针。见 [[../数学/向量的叉乘]]。
> 这里作者没用它，是因为环的边界是**曲线**（圆弧、样条），不是直线段，所以改用"左侧偏移 + 射线法"这套更通用的路子。两条思路殊途同归。

## 外层：`GetAnticlockwiseLoops()`

这个函数本身没有算法，只是**筛选器**：

```csharp
public IEnumerable<TLoop> GetAnticlockwiseLoops()
{
    foreach (var loopItem in Loops)
    {
        if (IsAnticlockwise(loopItem.Value))   // 逐个问"是不是逆时针"
        {
            yield return loopItem.Value;        // 是就吐出去
        }
    }
}
```

`yield return` 是懒执行（LINQ 那套），遍历所有环，把判定为逆时针的一个个交出去。旁边的 `GetClockwiseLoops()` 是镜像，条件是 `!IsAnticlockwise`。

真正要理解的是 `IsAnticlockwise()`。

---

## 前置：半边(trim) 和 IsReserve（30 秒回顾）

这个函数建立在 [[半边数据结构]] 上，用到的几个概念快速对齐：

- 一条几何边 `Edge` 被拆成**两个半边 trim**：正向（沿曲线参数增大方向）和反向（沿参数减小方向）。
- 一个环拼接时，可能用某条边的正向半边，也可能用反向半边。
- `trim.IsReserve == true` 表示"这条半边是**反着走**这条边的"。

这决定了后面切线方向要正着取还是反着取。

---

## 核心：`IsAnticlockwise()` 逐步拆解

### 第 1 步：收集信息，并找出最长边

```csharp
int edgeCount = tLoop.TrimIndices.Count;
Curve2d[] curve2ds = new Curve2d[edgeCount];
bool[] isReserves = new bool[edgeCount];
int maxLengthIndex = -1;
double maxLength = 0.0;
List<Point2d> vertexes = new List<Point2d>();

for (int i = 0; i < tLoop.TrimIndices.Count; i++)
{
    var trim = Trims[tLoop.TrimIndices[i]];
    curve2ds[i] = trim.Curve2d;          // 曲线
    isReserves[i] = trim.IsReserve;      // 是否反向
    double length = trim.Curve2d.GetTotalLength();
    if (length > maxLength) { maxLength = length; maxLengthIndex = i; }  // 记录最长边
    vertexes.Add(_indexPointDict[trim.StartVertexIndex]);   // 每个半边的起点坐标
}
```

把环拆成三条平行数组 `曲线 / 反向标记 / 起点`，同时记住**最长的那条边**。

> [!NOTE] 为什么选最长边？
> 后面要在它**中点**处求切线再偏移。最长边的中点离两个拐角最远，切线方向最稳定（不会被局部尖角/弧度带偏），偏移出去的测试点最不容易"跑出环"或卡进凹角。

---

### 第 2 步：在最长边中点求切线，再求垂直方向

```csharp
var interval = curve2ds[maxLengthIndex].GetInterval();          // 参数区间 [下界,上界]
var middleParameter = (interval.LowerBound + interval.UpperBound) / 2;  // 中点参数
PointOnCurve2d pointOnCurve2d = new PointOnCurve2d(curve2ds[maxLengthIndex], middleParameter);
var direction = pointOnCurve2d.GetDerivative(1);   // 一阶导 = 切向量 = 行走方向
var perpendicularVector = direction.GetPerpendicularVector().GetNormal(); // 垂直向量并单位化
if (isReserves[maxLengthIndex])
{
    perpendicularVector = -perpendicularVector;    // 反向半边则翻转，统一到"左侧"
}

var middleP = pointOnCurve2d.Point;                // 中点坐标
double offset = Math.Min(maxLength / 2, 1.0);      // 偏移量，封顶 1.0
var testP = middleP + perpendicularVector * offset; // 左侧测试点
```

逐行对应你熟的向量操作：

| 代码 | 数学含义 | 已有概念 |
|:---|:---|:---|
| `GetDerivative(1)` | 一阶导 = **切向量** | 导数/方向 |
| `GetPerpendicularVector()` | 把切向量**转 90°** 得垂直向量 | 正交、垂直 |
| `GetNormal()` | 单位化 | 单位向量 |
| `-perpendicularVector` | 取反 | 向量反向 |

关键在 `if (isReserves[maxLengthIndex])` 那行：

- `direction` 是**沿曲线参数增大**的方向，不一定是环的行走方向。
- 如果这条半边是反向走的（`IsReserve == true`），环实际行走方向是 `-direction`，那"左侧"也跟着反了，所以要 `perpendicularVector = -perpendicularVector`。
- 结果：`perpendicularVector` 始终指向**环行走方向的左侧**。

最后 `testP = middleP + perpendicularVector * offset`，就是"从最长边中点往左侧挪一小步"。

> [!tip] offset 为什么封顶 `Math.Min(maxLength/2, 1.0)`？
> 防止偏移量太大，直接越过环的对面。`1.0`（一个单位）作为安全上限，保证 `testP` 基本还贴在最长边附近、落在环这一侧。

---

### 第 3 步：从 testP 找一条"安全"的射线方向

```csharp
List<double> angles = new List<double>();
foreach (var point2d in vertexes)
{
    var toVertex = point2d - testP;      // 从 testP 指向各顶点的向量
    angles.Add(toVertex.Angle);          // 记录方位角
}
angles.Sort();

Vector2d testDirection = new Vector2d(17,29).GetNormal();  // 初始随便一个方向
double maxAngleGap = 0.0;
for (int i = 0; i < angles.Count; i++)
{
    double nextAngle;
    if (i == angles.Count - 1)
        nextAngle = angles[0] + Math.PI * 2;   // 首尾相接，绕 2π 回来
    else
        nextAngle = angles[i + 1];

    double gap = nextAngle - angles[i];
    if (gap > maxAngleGap)
    {
        maxAngleGap = gap;
        double middle = (nextAngle + angles[i]) / 2;   // 取最大空隙的正中间
        testDirection = new Vector2d(Math.Cos(middle), Math.Sin(middle));
    }
}
```

站在 `testP` 往四周看，每个顶点都在某个方向上（`Angle` 是方位角）。把这些角度排序后，找**相邻顶点之间最大的那条空隙**，取空隙正中间作为射线方向。

> [!important] 为什么这么绕？
> 射线法（下一步）要数"射线和环的交点个数"。如果射线**正好穿过某个顶点**，这个交点算 0 个、1 个还是 2 个就说不清了（歧义）。
> 选"离所有顶点都最远的方向"（最大空隙的正中），就能**保证射线不穿过任何顶点**，计数一定准确。
> 那个初始 `new Vector2d(17,29)` 是随便取的一对互质数，只是兜底初值（避免退化情况下恰巧平行某条边）。

---

### 第 4 步：射线法数交点

```csharp
int intersectCount = 0;
Ray2d testRay = new Ray2d(testP, testDirection);   // 从 testP 沿 testDirection 射出去
foreach (var curve2d in curve2ds)
{
    var intersectRt = IntersectTools.Intersect(testRay, curve2d);  // 和每条曲线求交
    intersectCount += intersectRt.Count;
}

return intersectCount % 2 == 1;   // 奇数 = 在内部 = 逆时针
```

这就是经典的**射线法（point-in-polygon）**，核心规则：

| 交点个数 | testP 位置 |
|:---|:---|
| **奇数** | 环**内部** |
| **偶数**（含 0） | 环**外部** |

直觉：从环内任意一点往无穷远处画射线，必然要"穿出"边界奇数次；从环外出发，穿进穿出成对，是偶数次。

注意和"多边形"版本的区别：环的边是真实的 `Curve2d`（可能是圆弧、样条），所以射线和**每条曲线**求交，而不是只连顶点——弯曲的环也能正确判断。

## 完整汇总：手动跟踪表

把整条逻辑链串起来：

| 步骤 | 做了什么 | 目的 |
|:---|:---|:---|
| 1 | 收集每条半边的 曲线/反向标记/起点，找出最长边 | 准备数据 |
| 2 | 最长边中点求切线 → 转垂直 → 按 IsReserve 统一到左侧 → 偏移出 `testP` | 造出"左侧那一点" |
| 3 | 从 `testP` 看各顶点角度，取最大空隙正中做射线方向 | 保证射线不穿过顶点 |
| 4 | 射线和每条曲线求交，数个数，奇偶判定 | 判断 `testP` 在内还是外 |

最后 `return intersectCount % 2 == 1` 的语义：

- `testP` 在**内部** → 左侧是内部 → 环是**逆时针** ✅
- `testP` 在**外部** → 左侧是外部 → 环是**顺时针** ❌

---

## 两个前提（隐含假设）

1. **环是简单闭合的**：不自交、不退化。自交环时"内部/外部"本身不唯一，射线法结果会失真。
2. 它判断的是**带真实曲线的环**，所以比"鞋带公式算有向面积的正负"更通用——鞋带公式只对直线多边形成立，这里能处理圆弧/样条边界。

## 闪卡

> [!question]- 判断环方向的核心思想是什么？
> 沿环行走方向朝左侧偏移一小步得到 `testP`，再用射线法判断它在环内还是环外：在内部 = 逆时针，在外部 = 顺时针。

> [!question]- 为什么偏移时要按 IsReserve 翻转垂直向量？
> `direction` 是沿曲线参数增大方向，不一定是环的行走方向。IsReserve 为 true 时环反向走，左侧也反了，所以要取反，保证垂直向量始终指向环行走方向的左侧。

> [!question]- 为什么要选最长边来造测试点？
> 最长边中点离拐角最远，切线方向最稳定，偏移出的测试点不容易跑出环或卡进凹角。

> [!question]- 为什么射线方向要取顶点角度的"最大空隙正中"？
> 保证射线不穿过任何顶点，避免交点计数歧义（穿过顶点算几个交点说不清）。

> [!question]- 射线法的奇偶规则是什么？
> 从 `testP` 发一条射线，与环的边界交点数：奇数 = 内部，偶数 = 外部。
