## 1. `yield return` 

 `yield return` 是编译器自动生成 `IEnumerator` 的语法糖（见 [2.6 迭代器 iterator](../../Csharp/接口、枚举器和迭代器.md#2.6%20迭代器%20iterator)）。这里用邻接表的 `GetNeighbors` 方法具体演示。

### 1.1 原始代码

```csharp
public IEnumerable<(T vj, double val)> GetNeighbors(T vi)
{
    var cur = graph[GetVertexIndex(vi)].first;
    while (cur != null)
    {
        yield return (cur.endVertex, cur.val);
        cur = cur.next;
    }
}
```

### 1.2 如果用 `foreach` 调用它

```csharp
var graph = new GraphAdjacencyList<string>(new[] { "A", "B", "C" });
graph.AddEdge("A", "B", 3);
graph.AddEdge("A", "C", 5);

// GetNeighbors 返回 IEnumerable，所以可以用 foreach
foreach (var (vj, val) in graph.GetNeighbors("A"))
{
    Console.WriteLine($"A→{vj}，权值={val}");
}
// 输出：
// A→C，权值=5      ← 注意：头插法导致逆序！先插入 B(3)，后插入 C(5)，但 C 在链表头部
// A→B，权值=3
```

### 1.3 `yield return` 的执行模型——"走一步，停一下"

```
调用 GetNeighbors("A") 时：
  → 并不执行方法体，而是返回一个"待命"的迭代器对象

foreach 第一次迭代（调用 MoveNext()）：
  → 方法体开始执行
  → cur = 链表第一个节点 (v₂)
  → 遇到 yield return (v₂, val) → 暂停！把 (v₂, val) 交给 foreach
  → 控制权返回给调用方

foreach 第二次迭代（再次调用 MoveNext()）：
  → 从上一次暂停的地方恢复
  → cur = cur.next（链表下一个节点 v₄）
  → 遇到 yield return (v₄, val) → 又暂停！交出 (v₄, val)

foreach 第三次迭代：
  → 恢复，cur = cur.next = null
  → while 条件为 false，退出循环
  → 方法结束（没有更多 yield return）→ MoveNext() 返回 false
  → foreach 终止
```

>[!NOTE] 
>**方法不是一次性执行完的**。`yield return` 像是一个"暂停点"：

### 1.4 如果没有 `yield return`？

 `GetNeighbors` 的 `yield return` 版本等价于编译器生成下面这个类：

```csharp
// 编译器自动生成的内部类（简化版）
class GetNeighborsIterator : IEnumerator<(T vj, double val)>
{
    private int state = 0;           // 状态机：0=初始，1=遍历中，-1=结束
    private EdgeNode cur;             // 对应方法中的 cur 变量
    private VertexNode head;          // 对应 graph[GetVertexIndex(vi)]
    public (T vj, double val) Current { get; private set; }

    public bool MoveNext()
    {
        switch (state)
        {
            case 0:  // 首次调用
                cur = head.first;
                state = 1;
                goto case 1;

            case 1:  // 遍历中
                if (cur != null)
                {
                    Current = (cur.endVertex, cur.val);
                    cur = cur.next;       // 为下一次 MoveNext 准备
                    return true;          // 还有元素
                }
                state = -1;
                return false;             // 遍历结束

            default:
                return false;
        }
    }

    // Reset、Dispose 省略...
}
```

>[!NOTE] 
>1. `yield return` 不是 return——它**不终止方法**，只暂停
>2. 方法的局部变量（`cur`）被编译器提升为类的字段，跨暂停保存
>3. 编译器生成的状态机（`state = 0, 1, -1`）跟踪"执行到哪一行了"
>4. 这一切都不用写——`yield return` 可以让程序员像写普通循环一样写迭代器

## 2. 头插法 vs 尾插法

代码中邻接表 `AddEdge` 方法用的是**头插法**。
两者本质上都是把新边节点挂到链表上，区别在于**挂在哪里**。

### 2.1 看图说话

**头插法**（当前代码的方案）：

![[../dot/头插法.svg]]

```csharp
// 头插法：O(1)，两步搞定
var edge = new EdgeNode(vj, val);
var head = graph[GetVertexIndex(vi)];

edge.next = head.first;   // ① 新节点指向原来的第一个
head.first = edge;         // ② head 指向新节点
```

**尾插法**（另一种方案）：

![[../dot/尾插法.svg]]

```csharp
// 尾插法：O(n)，需要先找到尾巴
var edge = new EdgeNode(vj, val);
var head = graph[GetVertexIndex(vi)];

if (head.first == null)         // 链表为空
{
    head.first = edge;
}
else
{
    var tail = head.first;
    while (tail.next != null)   // 遍历找到最后一个节点
        tail = tail.next;
    tail.next = edge;           // 挂在尾部
}
```

### 2.2 头插法为什么是 O(1)？

因为<span style="color:red;">始终知道头部在哪（`head.first`）</span>，不需要遍历。不管链表有多长，插入永远是两步。

尾插法则必须先**遍历整个链表**找到最后一个节点（`tail.next == null`），链表越长越慢。

### 2.3 直观对比

假设依次插入 A→B, A→C, A→D 三条边：

```
插入顺序：先 B，再 C，再 D

头插法结果：head → [D] → [C] → [B] → null    // 逆序！
尾插法结果：head → [B] → [C] → [D] → null    // 保持插入顺序
```

### 2.4 为什么邻接表用头插法？

|       | 头插法      | 尾插法      |
| ----- | -------- | -------- |
| 时间复杂度 | O(1)     | O(n)     |
| 插入后顺序 | 逆序       | 保持原序     |
| 适用场景  | 不关心邻接边顺序 | 需要保持插入顺序 |

对于图的邻接表来说，**通常不关心邻接边的先后顺序**（遍历时每条边都要访问），所以选头插法——简单、快。

>[!tip] 头插法和尾插法对图的遍历结果是有影响的。如DFS，选择结点v1，沿着一条路径走到尾，由于头插法和尾插法导致边的顺序不一致，就会改变DFS的顶点访问顺序。

## 3. 整体结构回顾

![[../dot/邻接表结构.svg]]

代码分三层：

| 层 | 类 | 角色 |
|---|---|---|
| 边节点 | `EdgeNode` | 存一条边的终点 + 权值 + next 指针 |
| 顶点节点 | `VertexNode` | 存一个顶点 + 指向第一条边的指针 (`first`) |
| 图 | `GraphAdjacencyList<T>` | 顶层：持有顶点数组 `VertexNode[]` |

类比：`VertexNode[]` 像一排抽屉，每个抽屉里挂着一串钥匙环（`EdgeNode` 链表），每个钥匙环记录"连到谁、权值是多少"。
