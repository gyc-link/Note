## 引入

写程序就是在和数据打交道。数据怎么组织、怎么存取，直接决定了程序能跑多快、代码好不好写。

> [!important] 两个核心问题
> 1. **数据在内存里怎么摆？** → 数据结构
> 2. **数据能做什么操作？操作的语义是什么？** → 抽象数据类型


---

## 数据结构 Data Structure

### 定义

> [!help]- 什么是数据结构
> 数据结构是**数据在计算机中存储和组织的方式及其相关操作**。

进一步来说，数据结构关注的是数据的逻辑结构、物理结构及其相互关系，并针对这些结构定义相应的操作和算法，确保经过操作后数据依然保持原有的结构特性。

数据结构描述了三件事：
1. **逻辑结构**：数据元素之间是什么关系（一对一？一对多？多对多？集合结构？）
2. **物理结构**：这些关系在内存里怎么存（连续存？指针链起来？）
3. **操作**：在这种组织方式上能做什么、怎么做（怎么查、怎么增、怎么删）

### 逻辑结构的分类

| 分类 | 关系 | 例子 |
|:---|:---|:---|
| 线性结构 | 一对一 | 数组、链表、栈、队列 |
| 树形结构 | 一对多 | 二叉树、B树、堆 |
| 图形结构 | 多对多 | 有向图、无向图、带权图 |
| 集合结构 | 同属一个集合 | 散列表、位图 |

> [!NOTE] 线性 vs 非线性
> 线性结构只有一个前驱和一个后继（像一条线），非线性结构可以有多个后继或前驱（像网或树）。

### 物理结构的分类

> [!important] 两种底层存储方式
> 所有数据结构在内存里，最终只有两种落地方案：**顺序存储**和**链式存储**。

| | 顺序存储 | 链式存储 |
|:---|:---|:---|
| 底层 | 连续内存（数组） | 指针串联（结点） |
| 访问 | 随机访问 O(1) | 顺序访问 O(n) |
| 插入/删除 | 需要移动元素 O(n) | 改指针即可 O(1) |
| 空间 | 需要预分配，可能浪费 | 有指针开销，但按需分配 |
| 代表 | 数组、`ArrayList` | 链表、树、图 |

> [!NOTE] 索引存储和散列存储
> 有些教材会单独列出这两种，但本质上它们也是建立在顺序或链式之上的：
> - **索引存储**：额外维护一张索引表（如数据库的 B+ 树索引）
> - **散列存储**：通过散列函数算出地址，底层依然是数组（顺序存储）

### 为什么命名不只看逻辑结构？

> [!question] 一个常见困惑
> 数据结构有三要素：逻辑结构、物理结构、操作。那为什么有的数据结构，逻辑结构是树、物理结构也用到了树的思想，但既不叫"树"也不按树的逻辑结构来理解？

答案藏在**操作 + 约束**里。

> [!important] 核心原则
> 逻辑结构 + 物理结构决定了数据结构"长什么样"，但**操作集合 + 约束条件**决定了它"是什么"。
>
> 命名反映的是后者——因为使用者关心的是"我能用它做什么"，而不是"它内部怎么摆的"。

#### 案例 1：二叉堆——逻辑是树，物理是数组，但叫"堆"

| 维度 | 二叉堆（大顶堆） | 二叉搜索树 |
|:---|:---|:---|
| 逻辑结构 | 完全二叉树 | 二叉树 |
| 物理结构 | 数组（父子关系用下标算） | 链式（left/right 引用） |
| 核心约束 | **堆序性**：父 ≥ 子 | **搜索序**：左 < 根 < 右 |
| 核心操作 | `Insert`、`ExtractMax`、`Peek` | `Insert`、`Delete`、`Search` |
| 名字由来 | 堆序性质（heap property） | 支持按 key 搜索 |

堆不叫"树"，因为它根本不支持"搜索某个值"这个树的标志性操作。堆只关心最大/最小——这是**优先级队列**的操作，不是树的操作。

```csharp
// 二叉堆（大顶堆）—— 逻辑是完全二叉树，存储是数组
// 但它的操作是"优先级队列"式的，不是"树"式的
public class MaxHeap
{
    private List<int> _data = new();

    public void Insert(int value)
    {
        _data.Add(value);
        Swim(_data.Count - 1);  // 上浮
    }

    public int ExtractMax()
    {
        int max = _data[0];
        _data[0] = _data[^1];
        _data.RemoveAt(_data.Count - 1);
        Sink(0);  // 下沉
        return max;
    }

    // 注意：没有 Search(int key)！
    // 堆不提供按值查找——这不是它的职责
    private void Swim(int i) { /* 与父节点比较，必要时交换 */ }
    private void Sink(int i) { /* 与子节点比较，必要时交换 */ }
}
```

> [!NOTE] 关键区别
> 堆的操作是优先级队列的操作（insert/extract-max），不是树的操作（search/traverse）。逻辑上像树只是实现堆序性的一种手段，不是本质。

#### 案例 2：并查集——逻辑是森林，物理是数组，但叫"并查集"

| 维度 | 并查集 | 一般的树 |
|:---|:---|:---|
| 逻辑结构 | 多棵树的集合（森林），每棵树代表一个集合 | 单棵树或多棵树 |
| 物理结构 | 数组 `parent[i]`（存父节点下标） | 链式引用 |
| 核心操作 | `Union`（合并两个集合）、`Find`（找代表元） | `Insert`、`Delete`、`Search`、`Traverse` |
| 名字由来 | 操作是"并"和"查"，不是"遍历"或"搜索" |

并查集不叫"树"，因为它的操作是**集合操作**（union/find），不是树操作。树的形态只是实现集合合并的一个技巧——让查找代表元的路径尽量短。

```csharp
// 并查集：数组存储，逻辑上是森林
// 但它是"集合"的抽象，不是"树"的抽象
public class UnionFind
{
    private int[] _parent;
    private int[] _rank;

    public int Find(int x)
    {
        if (_parent[x] != x)
            _parent[x] = Find(_parent[x]); // 路径压缩
        return _parent[x];
    }

    public void Union(int x, int y)
    {
        int rootX = Find(x);
        int rootY = Find(y);
        if (rootX == rootY) return;
        // 按秩合并
        if (_rank[rootX] < _rank[rootY])
            _parent[rootX] = rootY;
        else if (_rank[rootX] > _rank[rootY])
            _parent[rootY] = rootX;
        else { _parent[rootY] = rootX; _rank[rootX]++; }
    }

    // 注意：没有遍历、没有搜索特定节点
    // 只有"这两个元素在同一集合吗？"和"合并这两个集合"
}
```

> [!NOTE] 关键区别
> 并查集的操作是集合的操作（union/find），树只是"顺便用来实现"的。它的树是倒着长的（子指向父），而且路径压缩会让树越来越不像树。

#### 汇总

| 数据结构 | 逻辑结构 | 物理结构 | 为什么名字 ≠ 逻辑结构 |
|---|---|---|---|
| 堆 | 完全二叉树 | 数组 | 操作是优先级队列的，不是树的 |
| 并查集 | 森林 | 数组 | 操作是集合的，不是树的 |
| 哈希表 | 数组 | 数组+链表 | 操作是 key-value 映射，不是数组下标访问 |
| 图 | 顶点+边 | 邻接矩阵/邻接表 | 物理用了数组/链表，但操作是图的（BFS/DFS/最短路径） |

#### 反过来看

> [!tip] 为什么二叉搜索树叫"树"？
> 因为它的操作（按 key 搜索、范围查询、前驱后继）就是树的标志性操作——你确实在"遍历树的节点来找东西"。

> [!important] 一句话总结
> **数据结构命名 = 操作决定身份，形状只是实现细节。**

## 抽象数据类型 Abstract Data Type (ADT)

### 定义

> [!help]- 什么是 ADT
> 抽象数据类型定义了一组**数据**和在这组数据上的**操作**，但**不规定这些操作如何实现**。它只回答"能做什么"，不回答"怎么做"。

ADT 是一个**数学概念**，不是编程概念。它用数学语言描述行为，屏蔽了实现细节。

> [!important] ADT = 数据 + 操作的语义
> 一个 ADT 由两部分组成：
> 1. **值域**：这种类型的所有可能值构成的集合
> 2. **操作集**：定义在这些值上的一组操作，包括操作的签名和语义（行为规约）

### 例子：栈 ADT

栈作为一个 ADT，用数学语言描述：

```
值域：任意类型的元素的序列 (a₁, a₂, ..., aₙ)

操作：
  Push(S, x)  : 在序列末尾插入元素 x
  Pop(S)      : 删除并返回序列末尾的元素
  Top(S)      : 返回序列末尾的元素（不删除）
  IsEmpty(S)  : 判断序列是否为空

语义（规约）：
  Pop(Push(S, x)) = x
  Top(Push(S, x)) = x
  IsEmpty(∅) = true
  IsEmpty(Push(S, x)) = false
```

> [!NOTE] 注意
> ADT 的描述里没有提到数组、链表、指针——这些是实现层的事。ADT 只管行为对不对。

### C# 里 ADT 是如何体现的

在 C# 中，接口（`interface`）就是 ADT 的直接对应物：

```csharp
// ADT：只定义"能做什么"
public interface IStack<T>
{
    void Push(T item);
    T Pop();
    T Peek();      // 即 Top
    bool IsEmpty { get; }
}
```

```csharp
// 数据结构：具体实现"怎么做"
public class ArrayStack<T> : IStack<T> { /* 用数组实现 */ }
public class LinkedStack<T> : IStack<T> { /* 用链表实现 */ }
```

## ADT vs 数据结构：核心区别

> [!important] 一句话
> **ADT 定义行为规范（What），数据结构是行为和实现的结合体（How）。**

| 维度 | ADT | 数据结构 |
|:---|:---|:---|
| 关注点 | **做什么** | **怎么做** |
| 层次 | 逻辑/抽象层 | 物理/实现层 |
| 语言 | 数学描述 | 编程语言实现 |
| 例子 | 栈、队列、字典、集合 | 数组、链表、二叉搜索树、散列表 |
| C# 对应 | `interface`、抽象类 | 具体的 `class`、`struct` |

> [!warning] 常见的混淆
> "栈是数据结构还是 ADT？"——栈本身是 ADT。用数组实现的栈才是数据结构。日常说话"用栈"其实混用了这两个层次，但在严格意义上，**栈是 ADT，数组栈/链表栈是数据结构**。

### 一个 ADT 可以由多种数据结构实现

```
             Stack (ADT)
            /            \
    ArrayStack          LinkedStack
   (顺序存储)           (链式存储)

            Queue (ADT)
           /          \
    ArrayQueue       LinkedQueue
   (循环数组)         (链表)

           Dictionary (ADT)
          /               \
    HashTable            TreeMap
   (散列表)           (红黑树/BST)
```

> [!info] 这正是 ADT 的价值
> 上层代码依赖 ADT 编写，底层换实现时上层完全不用动。这就是**封装**和**面向接口编程**的理论基础。

## 常见 ADT 及其可能的实现

| ADT | 核心操作 | 可能的实现（数据结构） |
|:---|:---|:---|
| **栈 Stack** | Push, Pop, Peek | 数组、链表 |
| **队列 Queue** | Enqueue, Dequeue | 循环数组、链表 |
| **双端队列 Deque** | 两端插入/删除 | 双向链表、循环数组 |
| **优先队列 Priority Queue** | Insert, ExtractMin | 堆、无序数组 |
| **列表 List** | 按索引存取、插入、删除 | 数组、链表 |
| **集合 Set** | Add, Remove, Contains | 散列表、平衡树 |
| **字典/映射 Map** | Put, Get, Remove | 散列表、平衡树、跳表 |
| **图 Graph** | 遍历、最短路径 | 邻接矩阵、邻接表 |

> [!NOTE] ADT 是"接口层"，数据结构是"实现层"
> 选一个 ADT 是选"我需要什么操作"，选一个数据结构是选"我要什么性能特征"。

---

## 为什么理解这个区别很重要

> [!important] 三点理由

**1. 设计上：分而治之**

先确定程序需要哪些操作（选 ADT），再根据性能需求选具体实现（选数据结构）。两个决策独立，不会搅在一起。

**2. 性能上：知道代价**

同样的 ADT，不同实现的性能天差地别：

| 操作 | ArrayStack | LinkedStack |
|:---|:---|:---|
| Push | O(1)* | O(1) |
| Pop | O(1) | O(1) |
| 空间 | 可能浪费 | 指针开销 |

> *均摊 O(1)，扩容时需要复制

**3. 阅读上：看懂代码的意图**

看到 `IList<T>` 就知道"这里需要一个有顺序、能按索引存取的容器"，看到 `ISet<T>` 就知道"这里只关心成员关系，不关心顺序"。接口暴露了设计者的意图。

## 总结

```
        抽象层                          实现层
    ┌──────────┐                  ┌──────────┐
    │   ADT    │  ——— 规约 ———→   │ 数据结构  │
    │ 做什么    │  ←—— 实现 ———   │ 怎么做    │
    │ 接口/契约 │                  │ 存储/算法  │
    └──────────┘                  └──────────┘
         ↑                              ↑
    栈、队列、字典              数组、链表、树、散列表
```

> [!important] 一个贯穿始终的思想
> **针对 ADT 编程，而不是针对具体的数据结构编程。** 这和"针对接口编程，而不是针对实现编程"是同一件事——只不过 ADT 把这个原则用在了数据组织上。
