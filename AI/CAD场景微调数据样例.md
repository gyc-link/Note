# CAD 场景微调数据样例（20 条）

## 这份数据是干什么的

配套 [[微调大模型入门]] 用的。目的是让你手上有**一份能直接喂进训练脚本的真实数据**，跑通第五节那条最小 LoRA 流程，亲眼看到"模型学会一种固定的回答结构"。

文件：`cad-train.jsonl`——一行一条 JSON，可直接被 `load_dataset("json", data_files="cad-train.jsonl")` 读进去。

## 设计意图：这份数据想教模型学什么

>[!important] 看结构，不要看内容
>这 20 条的**输出结构完全一样**，每一条都是三段：
>
>```
>结论：一句话给出答案
>步骤：1. 2. 3. 可以直接照着做的顺序
>注意：这一个坑 / 边界情况
>```
>
>**这就是微调要学的东西**——不是 20 个 CAD 知识点，而是"**遇到任何 CAD 问题，都按 结论/步骤/注意 这三段来回答**"。
>
>内容千变万化（20 个不同的问题），结构只有一种写法（三段式）。手工写的 `output` 结构越统一，模型学到的习惯越稳定。

>[!warning] 反过来说
>- 想让模型每次都吐 JSON？那 20 条 `output` 就**必须都是同构的 JSON**，字段名一个字都不能飘。
>- 如果 `output` 一半写成段落、一半写成列表，模型学到的就是"在这两种风格里随机挑一个"——这正是第八节说的"输出格式忽好忽坏"的成因。

## 三个字段是怎么拼成一句话的

训练脚本里的 `to_text` 会把每条数据拼成这样，再交给模型：

```
system:    你是CAD插件开发助手。
user:      {instruction}
           {input}
assistant: {output}
```

所以 `instruction` 和 `input` 是**拼在一起**的，两部分的分工是：

| 字段 | 装什么 | 例子 |
| --- | --- | --- |
| `instruction` | 这类问题的"题目类型"，同一类可以重复出现很多次 | 创建一个新图层 |
| `input` | 这一条的具体参数，每条不同；不需要参数时留空字符串 | 图层名 MY_LAYER，颜色绿色 |
| `output` | 你期望它输出的标准答案 ← **模型学的是这个** | 结论：… 步骤：… 注意：… |

## 全部 20 条速览

| # | instruction | input | 期望输出的结论 |
| --- | --- | --- | --- |
| 1 | 解释我这段代码为什么抛 eLockViolation 异常 | 在调色板(PaletteSet)的按钮回调里直接修改数据库 | 文档被锁定时不能修改数据库，进回调要先锁文档。 |
| 2 | 事务忘记 Commit 会怎样 | using (Transaction tr = db.TransactionManager.StartTransaction()) { var ent = tr.GetObject(id, OpenMode.ForWrite) as Entity; ent.ColorIndex = 1; } | 不 Commit，所有修改在事务释放时被丢弃，图形看起来什么都没发生。 |
| 3 | GetObject 时 OpenMode 该选 ForRead 还是 ForWrite | — | 只读用 ForRead，要改属性用 ForWrite，用错了会抛 eNotOpenForWrite。 |
| 4 | 在当前图形里创建一条直线 | 起点 (0,0,0)，终点 (10,5,0) | 新建实体后要同时挂到块表记录上，并交给事务托管。 |
| 5 | 把选中的实体改成红色 | — | 改实体自身的颜色属性，用 ColorIndex 最省事。 |
| 6 | 遍历模型空间里所有实体 | — | 先打开 BlockTable 找到模型空间的 BlockTableRecord，再遍历它。 |
| 7 | 用 XData 给实体挂自定义数据 | — | 写 XData 之前必须先在 RegAppTable 里注册应用名，否则写入失败。 |
| 8 | 自定义数据该放 XData 还是扩展字典 | — | 少量简单标记用 XData，大量或结构化的数据用扩展字典。 |
| 9 | 把点从世界坐标系转换到当前用户坐标系 | — | 用 Editor.CurrentUserCoordinateSystem 的逆矩阵做变换。 |
| 10 | 让用户自己选实体然后处理 | — | 用 Editor.GetSelection() 让用户选，需要限定类型就传 SelectionFilter。 |
| 11 | 事务为什么一定要写在 using 里 | — | using 保证事务一定被释放，否则会一直占着数据库资源，修改也不会生效。 |
| 12 | 求两条直线的交点 | — | 用 Curve.IntersectWith，不要自己去解方程。 |
| 13 | 判断一个点是否在闭合多段线内部 | — | AutoCAD .NET 没有现成的判定，需要自己用射线法实现。 |
| 14 | 循环里逐个开事务改几百个实体，特别慢 | — | 整个批量操作放进一个事务，不要在循环里开事务。 |
| 15 | 创建一个新图层 | 图层名 MY_LAYER，颜色绿色 | 在 LayerTable 里加一条 LayerTableRecord。 |
| 16 | 往当前空间插入一个块参照 | 块名 TITLE_BLOCK，插入点 (0,0,0) | 先从 BlockTable 取到块定义，再 new BlockReference。 |
| 17 | 在 ObjectModified 事件里改对象为什么报错 | — | 事件回调运行在文档锁定范围之外，改数据库前必须锁文档。 |
| 18 | 判断两个向量是否垂直，以及怎么求它们之间的夹角 | — | 垂直看点乘是否为 0，夹角是点乘除以两个模长的乘积再取反余弦。 |
| 19 | 怎么在命令行给用户提示信息 | — | 用 Editor.WriteMessage，换行符要自己加。 |
| 20 | 把当前图形另存为一个新文件 | — | 用 Database.SaveAs，它不会改变当前正在编辑的图形。 |

## 数量说明

>[!note] 20 条只够"跑通流程"，不够"训出效果"
>这不是训练数据的规模，是**流程验证数据**。它要验证的是：环境对不对、脚本能不能跑、数据格式有没有拼错、loss 会不会降。
>20 条 + 3 轮，几分钟就能跑完，够你看到 loss 从 2.x 降到 0.x。
>流程确认通了之后，再照着同样的结构扩到 200~500 条真实数据（见 [[微调大模型入门]] 第六节）。

## 怎么判断它学到的是"结构"而不是"背答案"

用这 20 条训完之后，**问一个不在这 20 条里的 CAD 问题**，比如"怎么删除模型空间里的一个实体"：

| 输出 | 说明 |
| --- | --- |
| 也按 `结论 / 步骤 / 注意` 三段回答，而且步骤是能用的 | ✅ **学到了结构**，这才是微调成功 |
| 原封不动吐回这 20 条里的某一条 | ❌ 过拟合，它把答案背下来了 |
| 还是自由发挥的段落 | ❌ 没学到，回去查 `target_modules` 和数据格式 |

## 往下扩展的方向

按同样的三段式结构继续加，优先级从高到低：

1. **你自己踩过的坑**——比如 eLockViolation、事务忘 Commit、ForRead 下改属性。你自己踩过的坑最真实，也最值得让模型记住
2. **你项目里固定的代码模板**——比如你们标准的"事务 + 选择集 + 批量修改"的写法，让它照着写
3. **报错信息 → 排查路径**——把异常名和对应的原因配对，这是最能省时间的用法

>加数据的时候记住第九节那条：**别只加量，要加"同样结构"的量。** 结构飘一条，习惯就弱一分。
