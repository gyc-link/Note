### 引子
#### CAD的NETLOAD 命令

在 CAD 里执行 `NETLOAD`，选中二次开发的一个 DLL程序集，然后敲一个命令，CAD便能执行里面的方法，这中间发生了啥？

```
NETLOAD 加载.dll
        │
        ▼
  CAD 用反射扫描DLL
        │
        ▼
  找到贴了 [CommandMethod] 的方法
        │
        ▼
  注册到命令表
        │
        ▼
  输入命令 → 查表 → 执行
```

#### 涉及到的三个概念：

| 概念           | 干了什么                                                  |
| ------------ | ----------------------------------------------------- |
| **程序集（DLL）** | 代码打包成 .dll 文件，NETLOAD 把它装进 CAD 进程                     |
| **反射**       | CAD 在运行时翻阅DLL，看看里面有哪些类、哪些方法                           |
| **特性**       | `[CommandMethod("MYCMD")]` — 告诉 CAD 哪个方法是**命令**、叫什么名字 |

---

#### 为什么需要程序集？

>[!question]- DLL/程序集是什么
>DLL/程序集 是一个物理容器，编译器把代码变成CIL，打包成一个.dll或.exe文件，里面装着:
>- CIL代码
>- 类型元数据
>- DLL的整体信息和对其他程序集的引用
>- 资源文件


DLL 让代码独立于宿主程序存在。参考[[../../计算机/DLL 动态链接库]] 

AutoCAD 编译的时候预留了一个"加载外部 DLL"的口子--NETLOAD，这样便能够将后来的DLL加载进CAD进程中。

---

#### 为什么需要反射？

程序集加载进来之后，CAD并不知道程序集里有哪些类，哪些方法，所以**CAD 不可能硬编码后加载进来DLL内的方法名**。

通过反射遍历DLL的元数据。

```csharp
Assembly asm = Assembly.LoadFrom("外部.dll");   // 加载
foreach (Type t in asm.GetTypes())               // 遍历每个类
{
    foreach (MethodInfo m in t.GetMethods())     // 遍历每个方法
    {
        // 看看有没有贴 [CommandMethod]
    }
}
```

`Type`、`MethodInfo`、`Assembly` 这些就是反射的核心类，都在 `System.Reflection` 命名空间下。

**不用反射的话**，需要写一个配置文件（比如 XML），手工列出"命令名 → 类名 → 方法名"的对应关系，DLL 更新了配置文件也得跟着改——容易不同步。

---

#### 为什么需要特性？

反射能知道"这个类有哪些方法、方法叫什么、参数是什么"，但它无法回答：**这个方法是不是一个 CAD 命令？用户在命令行里输入什么才能调用它？**

`[CommandMethod("MYCMD")]`特性能解决这个问题。它往方法上贴了一个标签：

```csharp
[CommandMethod("MYCMD")]           // ← 这个标签说：我叫 MYCMD
public void MyCommand() { ... }
```

CAD 用反射扫到 `[CommandMethod]` 这个特性，就知道：这个方法要注册成命令，命令名叫 `MYCMD`。

**不用特性的话**，可能要靠命名约定（比如所有 `Cmd_` 开头的方法自动当命令），或者手工配置文件。特性比约定更明确，比配置文件更不容易丢。

---

#### 整条链路

```
[CommandMethod("MYCMD")]     ← 贴的特性（编译时写进 DLL 元数据）
        │
        ▼
NETLOAD                       ← CAD 把 DLL 加载进进程
        │
        ▼
Assembly.LoadFrom("xxx.dll")  ← 程序集加载
        │
        ▼
asm.GetTypes()                ← 反射：遍历所有类
  └→ type.GetMethods()        ← 反射：遍历所有方法
       └→ GetCustomAttribute<CommandMethodAttribute>()  ← 反射读特性
              │
              ▼
         RegisterCommand("MYCMD", method)  ← 注册到命令表
              │
              ▼
         CAD中敲 MYCMD → 查表 → 调用方法
```

#### Type类

Type类被设计用来包含类型的特征，使用这个类的对象能获取程序使用的类型的信息

System.Type 类的部分成员

| 成 员               | 成员类型 | 描 述                              |
| ----------------- | ---- | -------------------------------- |
| **Name**          | 属性   | 返回类型的名字                          |
| **Namespace**     | 属性   | 返回包含类型声明的命名空间                    |
| **Assembly**      | 属性   | 返回声明类型的程序集。如果类型是泛型的，返回定义这个类型的程序集 |

| **GetProperties** | 方法   | 返回类型的属性列表                        |
| **GetMethods**    | 方法   | 返回类型的方法列表                        |

#### 获取Type对象

typeof运算符和GetType方法获得Type对象。
- object基类型包含了GetType方法，所以可以在任意类型的对象上使用GetType方法来获取它的Type对象。
- typeof运算符只需要提供类型名作为操作数，就会返回Type对象的引用。

```csharp
//1、typeof运算符
Type t = typeof(string);

//2、GetType方法
string a = “hello”;
Type t = a.GetType();

//3、查看t的类型
Console.WriteLine(t.GetType());
//打印结果是RunTimeType
```

>[!warning] 注意
>- Type是一个抽象类，因此打印出t的类型不是Type，而是RunTimeType
>- RunTimeType是继承自Type的，是.NET运行时内部的具体实现。
>- 不同类型，.NET内部具体实现不一定总是RunTimeType，但是基类总是Type

> [!INFO] 
> 不管创建的类型有多少个实例，只有一个Type对象会关联到所有这些实例。

#### 特性

>[!definition]- 什么是特性（attribute）
>- 可以直观地理解为贴在方法/类/属性上地一个标签。
>- 从技术上讲，特性是一个实例化在运行时（CLR）的，携带数据的类对象

将应用了特性的程序结构叫做目标（target）（一般是开发者写的程序）
设计用来获取和使用元数据的程序叫做特性的消费者（consumer）

编译器在将代码编译成程序集这个过程中，会获取源代码并且从特性产生元数据，然后将元数据放到程序集中（生产）。消费者程序通过反射获取特性的元数据以及其他组件的元数据（消费）。
>[!note] 编译器也是消费者
>编译期间，如果编译器发现代码A引用了另一个程序集里的代码B，并且代码B上贴着obsolete特性，编译器就会打印警告信息，此时，编译器消费了特性。

惯例，特性名使用Pascal命名法并且以Attribute后缀结尾。
##### 应用特性

- 通过在结构前放置特性片段来应用特性
- 特性片段由方括号包围特姓名和参数列表（可选）构成

>应用了特性的结构被称为特性装饰（decorated或adorned）
>大多数特性默认只对对紧跟在他们后面那个代码结构生效。
