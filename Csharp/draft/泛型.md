## 5. 泛型协变与逆变

### 5.1 问题

如果 `Dog` 继承自 `Animal`，那么 `Func<Dog>` 能转成 `Func<Animal>` 吗？

```csharp
Func<Dog> dogMaker = () => new Dog();
Func<Animal> animalMaker = dogMaker;  // 编译错误！
```

两个委托是同级的，没有继承关系，即使它们的类型参数之间有派生关系。

### 5.2 协变（Covariance）—— out T

T 只出现在输出位置（返回值），允许 泛型\<子类\> 转成 泛型\<父类\>：

```csharp
// Func 的定义中 TResult 前有 out 关键字
public delegate TResult Func<out TResult>();

Func<string> getString = () => "hello";
Func<object> getObject = getString;  // 合法：string → object

//lambda直接赋值给声明的委托变量，背后实际上是编译器隐式声明了一个委托实例，再将lambda作为参数传进去。所以下面这行做了两件事，一个是隐式实例化，还有一个是泛型的协变

Func<object> getString = () => "hello";
```

### 5.3 逆变（Contravariance）—— in T

T 只出现在输入位置（参数），允许 泛型\<父类\> 转成 泛型\<子类\>：

```csharp
public delegate void Action<in T>(T obj);

Action<object> printObject = obj => Console.WriteLine(obj);
Action<string> printString = printObject;  // 合法：object → string
```

`printString` 接收 `string` 参数，按 `Action<object>` 的逻辑执行，完全安全。

### 5.4 总结

| 修饰符 | 方向 | 含义 | 例子 |
|--------|------|------|------|
| `out T` | 协变 | 泛型\<子\> → 泛型\<父\> | `Func<string>` → `Func<object>` |
| `in T` | 逆变 | 泛型\<父\> → 泛型\<子\> | `Action<object>` → `Action<string>` |
| 无修饰符 | 不变 | 不能转换 | `List<string>` 不能转 `List<object>` |

- `out T` / `in T` 只能用在**接口和委托**上，普通的类不支持
- `List<T>` 既读又写，所以不能协变；`IEnumerable<out T>` 只能读，所以可以
- 数组协变是另一种机制（C# 从 Java 继承来的历史特性），与泛型协变不同

什么叫做泛型协变、逆变？泛型协变有什么作用或者说解决了什么问题？
- 首先由于out/in只用在==1;;接口和委托==上，因此其他类不支持协变，逆变，除了数组的协变。
- 先看数组的协变，声明一个数组A，里面的元素类型是object，object[] A;然后拿另外一个已经在堆上的数组B，存了一堆string，把数组B赋值给数组A，是行的通的，这就叫做数组的协变。注意数组协变只支持==1;;引用类型数组间的转换==。
- 那么看下面这个例子
```csharp
List<string> temp1 = new List<string>();
List<object> temp2 = temp1;
```
- 这个编译器会报错，虽然给我的感觉是跟数组差不多的，但是这已经反应了数组的协变是做了一些额外的处理的。如果上面的编译能够通过，代表着temp1可以使用add函数去添加object对象，那么这个集合里可能==1;;加入不是string的元素==，破坏了==1;;泛型的不变性（类型安全）==。
- 接着看c#预定义的Func委托，尖括号内最后一个泛型参数是用out修饰的，表示这个类型只作为返回值输出，只负责往外吐。如下：
```csharp
Func<string> getString = () => "hello";
Func<object> getObject = getString;
```
- 编译器不会报错。这就是泛型协变。因为作为返回值，string本来就是object。==1;;泛型类型随着泛型参数类型继承关系**同向**变化==。
- 根据泛型协变修改上面的例子后，编译也能通过了
```csharp
IEnumerable<string> temp1 = new List<string>();
IEnumerable<object> temp2 = temp1;
```
- 泛型的逆变，定义是==1;;泛型类型随着泛型参数类型继承关系**反向**变化==。Action里的参数使用in修饰，表示这个参数是作为输入参数，只负责往里吃。
```csharp
Action<object> printObject = obj => Console.WriteLine(obj);
Action<string> printString = printObject;
string temp = "hello";
printString(temp);
```
- 可以看出，泛型逆变本质上是==1;;能处理object的函数一定能够处理string。==
- 因此泛型的协变逆变解决了，在安全的前提下，==1;;让泛型类型之间也能按照继承关系转换。==
- 用盒子模型重新梳理一下，盒子是生产者，只读，所以允许把“装子类型的盒子”看成“装父类型的盒子”。盒子是消费者，只负责处理输入，所以允许把“能处理父类型的盒子”看成“能处理子类型的盒子”。
