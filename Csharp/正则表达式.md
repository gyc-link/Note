# 正则表达式

用**模式**去描述"你想找的字符串长什么样"。

## 基础字符

| 符号 | 含义 |
| --- | --- |
| `\d` | 任意**单个数字** |
| `.` | 任意**单个字符**（除换行） |
| `\w` | 字母、数字、下划线 |

## 数量限定符

| 符号 | 含义 |
| --- | --- |
| `+` | 前面内容 **1 次及以上** |
| `*` | 前面内容 **0 次及以上** |
| `?` | 前面内容 **0 次或 1 次** |
| `{n}` | 恰好重复 **n 次** |
| `{n,m}` | 重复 **n~m 次** |
| `*?` | 非贪婪匹配 |

## 其他

| 符号 | 含义 |
| --- | --- |
| `^` | 字符串开头；在 `[]` 内是取非操作 |
| `$` | 字符串结尾 |
| `[]` | 字符范围，匹配括号内**任意一个**字符 |
| `()` | 捕获组：框起内容生成捕获组，把多个字符当成一个整体 |
| `(?! )` | 否定前瞻条件判断 |
| `(?<!)` | 否定后顾条件判断 |
| `\b` | **单词边界**锚点 |

## C# 中的正则

统一规范：正则表达式全部写 `@"规则"`。

```csharp
Regex.IsMatch(text, regex)              // 有没有匹配到
Match m = Regex.Match(text, pattern);    // 找一个匹配
MatchCollection ms = Regex.Matches(text, pattern); // 找所有匹配
Regex.Replace(text, pattern, replacement) // 替换
```

### 反斜杠为什么要写两遍

C# 字符串里 `\` 是转义起始符（`\n` 是换行），正则本身也用 `\` 作转义（`\d` 表示数字）。两层叠加，写正则时每个反斜杠都得再补一个：

```csharp
"起拱\\d+\\.?\\d*mm"     // 普通字符串：反斜杠要双写
@"起拱\d+\.?\d*mm"       // 逐字字符串：所见即所得，推荐
```

拆开看 `\d+\.?\d*`：

| 片段 | 含义 |
| --- | --- |
| `\d+` | 一个或多个数字 |
| `\.?` | 0 或 1 个点。这里的反斜杠把 `.` 当**普通字符**，而不是"除换行外任意字符" |
| `\d*` | 0 或多个数字 |

> 这就是上面统一规范要求正则全部写 `@"规则"` 的原因——少一层转义，正则写法和平时的读法一一对应。

### 什么时候不该用正则

如果目的只是"判断这串字符是不是合法数字"，用 `double.TryParse` 更短更稳：

```csharp
return double.TryParse(num, out _);
```

正则的强项是**从文本里捞出结构化的片段**（比如从备注文字里抽出"起拱 25mm"）；拿来做格式校验会写得又长又难维护。

> 目前软件里用正则从备注中提取信息。如果客户要求变化，代码里的这些正则都要跟着改——但比起在 C# 里手写解析，正则仍然是最省事的方案，改动比较集中。
